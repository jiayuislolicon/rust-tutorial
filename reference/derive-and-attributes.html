#[derive] and attributes

From Lesson 29. Attribute = a note attached to the item below it, read by the compiler. #[derive(...)] is the kind of attribute that generates real impl blocks.

Three attributes you're already using

AttributeWhat it actually does
#[test]marks a function for the test runner to call
#[cfg(test)]includes the item below only when compiling for cargo test
#[derive(Trait, ...)]writes one or more impl Trait for Type blocks, mechanically

What derive produces is the same shape as a hand-written impl

#[derive(Debug, PartialEq)]
pub enum LineKind {
    Empty,
    Comment,
    Code,
}

// equivalent to writing, by hand:
// impl Debug for LineKind { ... }
// impl PartialEq for LineKind { ... }

Without it, assert_eq!(a, b) fails with two separate errors: error[E0369] (no PartialEq, can't compare) and error[E0277] (no Debug, can't print the value if the check fails).

Common derivable traits

TraitWhat deriving it gives you
Debug{:?} printing
PartialEq== / !=, and therefore assert_eq!
Eqa stricter equality promise than PartialEq — required for a HashMap key
Clonea .clone() method
Copycopied on assignment instead of moved — only if every field is also Copy
Defaulta Type::default() constructor
Hashusable as a HashMap key

Why some traits can't be derived

#[derive] only works when the fields alone determine one mechanical answer. Display can't be derived because the exact text to print is a human choice, not something the fields decide — which is why impl fmt::Display for AppError in hello_cli/src/errors.rs is hand-written.

💡 error[E0277]: the trait bound ... is not satisfied on a #[derive(Something)] line usually means one of the type's own fields doesn't implement that trait — not that derive itself is broken.
