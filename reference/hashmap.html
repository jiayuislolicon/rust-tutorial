HashMap：鍵 → 值

use std::collections::HashMap;   // 不在預設引入範圍，要自己 use

常用操作

寫法 作用
HashMap::new() 建立空的 map，型別通常由後續用法推斷出來。
.insert(k, v) 寫入。鍵已存在就覆蓋舊值。
.get(&k) 讀取，回傳 Option<&V>。注意是參考： assert_eq!(m.get("a"), Some(&2))。
.len() 有幾組對應。
.iter() 逐一給出 (&K, &V) 的 tuple。順序不固定。

計數：entry().or_insert()

let mut counts: HashMap<String, usize> = HashMap::new();

for word in content.split_whitespace() {
    *counts.entry(word.to_string()).or_insert(0) += 1;
}
部分 作用
.entry(k) 拿到「這個鍵的位置」的把手，不管它現在有沒有值。
.or_insert(0) 空的就先塞 0，然後回傳指向該值的可變參考 &mut V。
開頭的 * 解開那個可變參考，讓 += 1 落在數字上而不是參考上。少了它編譯不過。

順序：沒有

HashMap 不保證任何走訪順序 —— 不是插入序，不是字母序，而且同一支程式每次執行都可能不同。要穩定輸出就自己排： 

let mut pairs: Vec<(&String, &usize)> = counts.iter().collect();
pairs.sort();   // tuple 先比第一個元素，等於按鍵排序

for (word, count) in pairs {
    println!("{} {}", word, count);
}

需要「永遠照鍵排好」的話，標準庫另有 BTreeMap，介面幾乎一樣但走訪是有序的。

對照 TypeScript：最接近 Map<K, V>（set / get / size）。差別在 get —— TS 給 V | undefined 可以直接用，Rust 給 Option<&V>，要先處理「沒有」的情況。
