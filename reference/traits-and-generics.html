Trait 與泛型

來自 Lesson 28。Trait = 一個型別擁有的能力。泛型 = 一份程式碼服務多個型別。Trait bound = 把泛型限縮到「只要有這個能力就好」。

Trait：宣告與實作

trait Summarize {
    fn summary(&self) -> String;
}

impl Summarize for Report {
    fn summary(&self) -> String {
        format!("{}：共 {} 行", self.filename, self.line_count())
    }
}

跟 TypeScript 的 interface 加 implements 是同一件事：trait 只宣告簽名，impl Trait for Type 才補上實作。一個型別可以實作很多個 trait。

泛型函式：一份程式碼，多個型別

fn largest<T>(list: &[T]) -> &T {
    let mut largest = &list[0];
    for item in list {
        if item > largest {   // error[E0369]：<T> 沒有承諾支援 >
            largest = item;
        }
    }
    largest
}

沒有 trait bound 的 <T> 只承諾「這是某個型別」，沒有承諾它能被比較、印出或做任何操作。

加上 trait bound

fn largest<T: PartialOrd>(list: &[T]) -> &T {
    // 同一份 body，現在合法了
}

largest(&vec![34, 50, 25, 100, 65]);      // -> 100
largest(&vec!["rust", "cargo", "compiler"]); // -> "rust"
寫法意思
<T>任何型別，但你只能移動它、存起來，不能比較或印出
<T: PartialOrd>任何有 >/< 的型別
<T: Display>任何能用 {} 印出的型別
<T: Display + PartialOrd>同時滿足兩個條件，用 + 疊加

讀標準庫簽名時，把 bound 當成使用條件

簽名（節錄）bound 在告訴你什麼
impl<T: Ord> Vec<T> { fn sort(&mut self) }只有元素能排序的 Vec 才有 .sort()
impl<K: Eq + Hash, V> HashMap<K, V>key 必須能判斷相等、能算 hash，value 沒有限制
fn print_all<T: Display>(items: &[T])只有能印出的型別才能傳進來

看到編譯錯誤說某個方法不存在（E0599）或某個運算子不能用（E0369）时， 先去找函式簽名上的 trait bound —— 十之八九是你的型別沒有滿足它。

impl Trait：隱藏具體型別名的靜態派發

fn matching_lines(&self, pattern: &str) -> impl Iterator<Item = &str> {
    self.content.lines().filter(move |line| line.contains(pattern))
}

impl Trait 在回傳位置代表：「這個函式回傳的東西實作了某 trait，但我不在簽名上寫出具體型別。」 編譯器仍然知道具體型別，做的是靜態派發（零成本）。

在參數位置則是泛型的語法糖：

fn print_it(val: impl Display) { ... }
// 等價於
fn print_it<T: Display>(val: T) { ... }

impl Trait vs dyn Trait vs 泛型

寫法型別何時確定派發適用場景
<T: Trait> 編譯期（呼叫端指定） 靜態 一份函式服務多種型別，且呼叫時型別已知
impl Trait（回傳位置） 編譯期（函式內部決定） 靜態 回傳 iterator chain / closure 等寫不出名字的型別
Box<dyn Trait> 執行時 動態（vtable） 同一位置需要存放/回傳不同具體型別（依使用者輸入等）

經驗法則：寫不出名字 → impl Trait；執行時才選 → dyn Trait； 能寫出名字且呼叫端也需要知道 → 明確的泛型。
