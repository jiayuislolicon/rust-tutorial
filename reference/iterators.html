疊代器：filter / map / count / fold / collect

常用方法

方法 作用 惰性？
.iter() 從集合做出疊代器（借用元素，不取走）。 —
.filter(|x| ...) 只留下條件為 true 的元素，數量可能變少。 惰性
.map(|x| ...) 把每個元素換成另一個值，數量不變。 惰性
.count() 跑到底，回傳元素個數。 收尾
.fold(init, |acc, x| ...) 帶一個累加器走到底，每步用 closure 更新，回傳最終累加器。 收尾
.collect() 跑到底，把結果收成集合，需標註目標型別。 收尾

疊代器從哪裡來：.iter() 還是 lines()？

看你手上是什麼東西：

手上的東西 怎麼取得疊代器
Vec / 陣列 / slice / HashMap .iter()
String / &str 看你想怎麼切：.lines()、.chars()、.split_whitespace()、.split(',')、.bytes()
已經是疊代器（例如 lines() 的回傳值） 什麼都不用加，直接接 .filter()

.iter() 是集合共用的「借用每個元素」入口。字串沒有 .iter()，因為「一個字串的元素」有好幾種答案（行？字元？位元組？），必須由你指定 —— 那些方法名稱就是你的答案。 

s.lines().iter()  // 編譯錯誤：no method named `iter` found for struct `std::str::Lines`

lines() 回傳的已經是疊代器，再呼叫 .iter() 沒有意義。

惰性

let step = numbers.iter().map(|n| n * 2); // 什麼都還沒算

let doubled: Vec<i32> = step.collect();   // 到這裡才真的跑

filter / map 只是疊上規則。要有收尾方法（count、collect）或 for 迴圈，才會真的走過資料。中間步驟不會各自產生暫存集合。

數出符合條件的元素

let empty_count = self
    .content
    .lines()
    .filter(|line| matches!(Report::classify_line(line), LineKind::Empty))
    .count();

lines() 本身就是疊代器，不需要再 .iter()。

.fold()：帶著累加器走完一遍

iterator.fold(初始值, |acc, item| {
    // 用 item 更新 acc
    acc
})

兩個參數：初始值（決定累加器型別）和一個 closure。closure 每一步接收目前的累加器和一個元素，處理完必須把累加器交回來。走完後回傳最終累加器。

適用場景：你需要自訂累積邏輯——例如同時數好幾種類型、邊走邊更新 struct 欄位。 

self.content.lines().fold(
    LineStats { empty: 0, comment: 0, code: 0 },
    |mut acc, line| {
        match Report::classify_line(line) {
            LineKind::Empty => acc.empty += 1,
            LineKind::Comment => acc.comment += 1,
            LineKind::Code => acc.code += 1,
        }
        acc
    },
)

注意 mut acc 跟 let mut 一樣：宣告區域變數可修改。不是 &mut，沒有借用——是所有權 move 進出 closure。

.collect()：交給標準 collection 組裝

.collect() 把 iterator 消耗掉、收進一個實作了 FromIterator 的型別。你必須告訴它目標型別——用 let 標注或回傳型別推斷皆可。

目標型別 寫法
Vec<T> let v: Vec<_> = iter.collect();
String let s: String = chars.collect();
BTreeMap<K, V> let m: BTreeMap<_, _> = pairs.collect();

Vec<_> 裡的 _ 讓編譯器自己推斷元素型別。如果回傳型別已經寫清楚（如 fn foo() -> Vec<&str>），body 裡的 .collect() 不需要額外標注。

適用場景：結果是標準 collection、每個元素對應 collection 裡的一項。不需要自訂邏輯時優先用它。

.fold() vs .collect()

.fold() .collect()
你提供 初始值 + closure 目標型別
邏輯由誰寫 你自己（closure 內） 標準庫（FromIterator）
典型情境 多計數器、跨行累積狀態 篩完收進 Vec、轉型後組字串
對照 TypeScript：.filter()／.map() 跟 JS 陣列同名方法語意一致，.count() 相當於 .length。差別是 JS 每一步都立刻產生新陣列，Rust 要到收尾方法才執行。
