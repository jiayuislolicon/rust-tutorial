run() / main() 分離、stderr 與離開碼

標準寫法

fn run() -> Result<(), AppError> {
    // 原本的邏輯，可以用 ?
    let mut report = load_report(filename)?;
    // ...
    Ok(())
}

fn main() {
    if let Err(error) = run() {
        eprintln!("{}", error);
        std::process::exit(1);
    }
}

main() 沒宣告回傳型別就是回傳 ()，? 在裡面用不了。把邏輯搬進另一個回傳 Result 的函式（習慣命名 run()），main() 只負責呼叫它、決定失敗時怎麼呈現。

三個新東西

  • if let Err(error) = run() { ... }：match 的簡寫，只處理你在乎的那個變體，其他情況直接略過。
  • eprintln!(...)：跟 println! 一樣，但印到 stderr 而不是 stdout——輸出被重導向到檔案時，錯誤訊息仍然顯示在終端機上。
  • std::process::exit(1)：立刻結束程式，回報離開碼給呼叫者。0 是成功的慣例，任何非零值代表失敗，shell 用 $? 讀取。
不呼叫 process::exit，離開碼預設是 0——即使剛印完錯誤訊息。這是腳本判斷這支程式是否成功唯一看的東西，不是印出來的文字。
