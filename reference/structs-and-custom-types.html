struct 與 impl

定義與建立

struct Report {
    filename: String,
    content: String,
    line_count: usize,
}

let report = Report {
    filename: "notes.txt".to_string(),
    content: content,      // 或簡寫 content，如果變數名跟欄位名一樣
    line_count: 3,
};

report.filename     // . 取欄位
report.content
report.line_count

欄位型別：優先用 String，不是 &str

struct Note { title: &str }   // error[E0106]: missing lifetime specifier

用 String 就不用管 lifetime —— struct 自己擁有內容。
（詳見 reference/string-types.html）

impl：方法 vs 關聯函式

impl Report {
    // 方法：第一個參數是 self，用 值.方法() 呼叫
    fn summary(&self) -> String {
        format!("{}：共 {} 行", self.filename, self.line_count)
    }

    fn add_title(&mut self) {
        let title = format!("=== {} ===\n", self.filename);
        self.content.insert_str(0, &title);
    }

    // 關聯函式：沒有 self，用 型別::函式() 呼叫
    fn new(filename: &str, content: String) -> Report {
        let line_count = content.lines().count();
        Report { filename: filename.to_string(), content, line_count }
    }
}

report.summary()        // 方法：用 .
report.add_title()
Report::new(name, body)  // 關聯函式：用 ::

self 三種寫法

&self       只讀欄位             （跟 Lesson 11 的 & 同一套規則）
&mut self   要修改欄位
self        整個值被吃掉不還      （少見）

你早就在用的關聯函式

String::from(...)   String::new()   Vec::new()
都是「型別::函式」— 沒有 self，只是產生一個新實例。

Derived fields go stale

A field computed from another field is a cache. Nothing in the type keeps it fresh — &mut self lets a method change the source and leave the cache behind.

pub struct Report {
    pub content: String,
    pub line_count: usize,   // derived from content — a promise you keep by hand
}

pub fn add_title(&mut self) {
    self.content.insert_str(0, &title);   // content grew, line_count did not
}
Recompute on demandCache and refresh
Shapefn line_count(&self) -> usize { self.content.lines().count() }Field stays; every &mut self method updates it
Cost per callWalks the dataReads one number
Cost per new methodNothingOne line, and remembering it
Failure modeSlow, measurableSilent, wrong, no test fires
RequiresNothingPrivate fields, all writes via methods

Test the rule, not the number. assert_eq!(report.line_count(), empty + comment + code) can only pass when the two counts agree; assert_eq!(report.line_count(), 3) passes while the tool is still wrong.

Reading an unfamiliar struct: a count beside a collection, a total beside a list, a flag beside the data it describes — each one is a rule nothing enforces.
