命令列選項：解析 flag

骨架

let mut filename: Option<String> = None;
let mut count_only = false;

for arg in env::args().skip(1) {
    match arg.as_str() {
        "--count-only" => count_only = true,
        _ if arg.starts_with('-') => return Err(AppError::UnknownFlag(arg)),
        _ => filename = Some(arg),
    }
}

要加新選項，就在第一個分支下面多寫一行字面值分支。

要點

寫法 為什麼
env::args().skip(1) 第 0 個元素是程式自己的路徑。args() 是疊代器，直接 .skip(1) 就好，不必先 collect() 成 Vec 再用索引。
arg.as_str() args() 給的是 String，pattern 裡的字面值是 &str。少了它，編譯器會說 expected `String`, found `&str`。
_ if 條件 => 守衛（match guard）。pattern 成立且條件為 true 才走這個分支。守衛裡可以用作用域內任何變數。
Option<String> 存檔名 「還沒看到檔名」和「檔名是空字串」是兩件事。迴圈跑完再對這個 Option 做 match，None 就印用法。

分支順序

match 從上往下取第一個成立的分支，沒有優先級規則。 具體的字面值分支必須寫在 _ if ... 守衛之前，否則永遠輪不到。

打錯選項要當成錯誤

// errors.rs
UnknownFlag(String),

// Display 的 match 裡
AppError::UnknownFlag(flag) => write!(f, "不認識的選項：{}", flag),

回傳 Err 之後就交給既有的 main() —— 印到 stderr、離開碼 1。新增錯誤變體不需要動 main()。

選項一多、需要 -c 這種短名稱、或需要自動產生 --help 時，實務上會換成 clap 這類套件。手寫這一版的意義是先看懂它在做什麼。
