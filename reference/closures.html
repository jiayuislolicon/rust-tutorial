閉包 Closures

來自 Lesson 25。閉包 = 函式 + 它從周圍捕捉到的變數。

語法

let f = |x: i32| -> i32 { x + 1 };   // 完整
let f = |x: i32| x + 1;             // 省略回傳型別
let f = |x| x + 1;                  // 兩個都省略（最常見）
let f = || println!("hi");          // 沒有參數

參數型別可省略，因為編譯器看得到呼叫端。但只會推斷一次 —— 第一次用 f(1) 之後，x 就定死成 i32 了。

跟一般 fn 的差別

fn 閉包
讀得到周圍的區域變數 不行 可以
參數型別 一定要標 通常可省略
型別名稱 有（fn pointer） 編譯器生成的匿名型別，每個都不同 
error[E0434]: can't capture dynamic environment in a fn item
  = help: use the `|| { ... }` closure form instead

看到這個錯誤，就是把該寫閉包的地方寫成 fn 了。

Fn / FnMut / FnOnce

不用自己宣告，編譯器看主體怎麼用捕捉到的變數自動決定。讀簽名時才需要分辨。

名字 對捕捉到的變數 借用方式 呼叫次數
Fn 只讀 &T 無限次
FnMut 會改 &mut T 無限次
FnOnce 消耗掉 取得所有權 一次 
// FnMut：改到外面的變數，閉包本身要標 mut
let mut total = 0;
let mut add = |x: i32| total += x;
add(1); add(2);
println!("{}", total);          // 3

// FnOnce：呼叫第二次會編譯失敗
let owned = String::from("hi");
let consume = move || owned;
consume();
// note: closure cannot be invoked more than once because it moves
//       the variable `owned` out of its environment

move

強迫閉包取得用到的變數的所有權，而不是借用。用在閉包會活得比原本的變數久的時候 —— 最常見是 thread::spawn(move || ...) 和非同步。加了之後外面就不能再用那些變數了。

簽名怎麼讀

fn count_if(text: &str, test: impl Fn(&str) -> bool) -> usize {
    text.lines().filter(|line| test(line)).count()
}
片段 意思
impl 任何型別都行，只要符合後面的條件
Fn 能被呼叫，而且只讀取捕捉到的變數
(&str) 呼叫時要傳一個 &str
-> bool 回傳 bool
寫法 意思 用在哪
impl Fn(...) 某一個特定閉包型別，編譯期決定 參數位置
Box<dyn Fn(...)> 放在堆積上，執行期才知道是哪一個 存進 struct 或 Vec
F: FnMut(&T) -> bool 標準庫文件的寫法，同一件事 filter、retain 等

常用的收閉包的方法

// 過濾（產生新的疊代器）
let n = text.lines().filter(|line| line.starts_with("//")).count();

// 就地刪掉不符合的元素
let min = 2;
pairs.retain(|pair| *pair.1 >= min);

// 自訂排序：a.cmp(b) 由小到大，b.cmp(a) 由大到小
pairs.sort_by(|a, b| b.1.cmp(a.1));

// 依某個欄位排序（更好讀的版本）
pairs.sort_by_key(|pair| *pair.1);

// 轉換每個元素
let lens: Vec<usize> = words.iter().map(|w| w.len()).collect();

// 找第一個符合的
let first = words.iter().find(|w| w.len() > 3);
