Option 與 Result

同一個形狀，兩種語意

enum Option<T> {          enum Result<T, E> {
    Some(T),  // 有值          Ok(T),   // 成功
    None,     // 沒有值        Err(E),  // 失敗
}                         }

兩者都是兩個變體的 enum，都用 match 拆開，編譯器都強制窮盡（漏掉一個變體就編不過）。 選擇依據：缺席用 Option，失敗用 Result。缺席不一定是錯誤。

用 match 拆開

match args.get(1) {
    Some(name) => name,           // 分支的值 = 整個 match 的值
    None => {
        println!("用法：...");
        return;                    // 提早離開，型別不衝突
    }
}

match fs::read_to_string(path) {
    Ok(content) => println!("{}", content),
    Err(error)  => println!("讀不到：{}", error),
}

會 panic 的取值方式（謹慎使用）

args[1]                  // 越界 → panic
opt.unwrap()             // None → panic
opt.expect("訊息")        // None → panic，附自訂訊息
res.expect("訊息")        // Err  → panic，附自訂訊息

只在「這裡若沒有值就是程式的 bug」時才用。可預期的使用者錯誤（檔案不存在、參數沒給、輸入不是數字）一律用 match。

不會 panic 的取值方式

args.get(1)                     // → Option<&String>，越界給 None
opt.unwrap_or(&default)         // None → 用你給的預設值
opt.is_some() / opt.is_none()   // → bool，只想知道有沒有

常見回傳 Option / Result 的 API

vec.get(i)                 → Option<&T>      索引可能越界
env::args().nth(1)         → Option<String>  參數可能沒給
"42".parse::<i32>()        → Result<i32, _>  字串可能不是數字
fs::read_to_string(path)   → Result<String,_> 檔案可能讀不到
io::stdin().read_line(&mut s) → Result<usize,_> 讀取可能失敗
