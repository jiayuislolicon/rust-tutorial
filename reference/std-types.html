標準庫型別地圖

來自 Lesson 24。看到陌生型別時的定位工具。

三個問題

問題 看什麼 對照
誰擁有這份資料？ 開頭有沒有 & String 擁有 / &str 借用
數量能不能變？ 長度有沒有寫進型別 [i32; 3] 固定 / Vec<i32> 可變

容器一覽

型別 做什麼 什麼時候用
Vec<T> 可增長序列，有順序，可索引 預設選項
&[T] 唯讀視窗（slice） 函式參數
[T; N] 長度寫死在型別裡 數量永遠固定
String / &str 擁有 / 借用的文字 同 Vec / &[T] 的關係
HashMap<K, V> 鍵找值，最快，無順序 只在乎查得快
BTreeMap<K, V> 鍵找值，永遠按鍵排序 要有序輸出或範圍查詢
HashSet<T> 只記有沒有，自動去重 「看過了嗎」、去重
VecDeque<T> 頭尾都能快速進出 佇列、需要 push_front
Option<T> 有 T 或什麼都沒有 不存在是正常狀況
Result<T, E> 成功帶 T，失敗帶 E 失敗要說明原因
Box<T> 資料放遠處，這裡留指標 大小算不出來時

為什麼分這麼細

編譯器必須在編譯期知道每個值佔多少空間。這一條推出了整個型別系統的形狀。 

size_of::<[i32; 3]>()   // 12  ← 資料本人就在這
size_of::<Vec<i32>>()   // 24  ← 指標 + 長度 + 容量
size_of::<Vec<String>>()// 24  ← 裝什麼都一樣
size_of::<String>()     // 24  ← 就是 Vec<u8>
size_of::<&str>()       // 16  ← 指標 + 長度（借的，不會長大）
size_of::<&i32>()       //  8  ← 純指標

Vec 本身大小固定（永遠 24），內容物數量才可變。這就是它能放進固定槽位又能無限長大的原因。

算不出大小時編譯器會直接擋： 

error[E0072]: recursive type `List` has infinite size
help: insert some indirection (e.g., a `Box`, `Rc`, or `&`) to break the cycle

常見取捨

選擇 得到 付出
BTreeMap 而非 HashMap 走訪永遠按鍵有序，不用自己排 插入與查詢比 HashMap 慢一些
&[T] 而非 &Vec<T> 當參數 陣列和 Vec 都能傳進來 拿不到 Vec 專屬方法（如 push）
HashSet 而非 HashMap 語意清楚，不用假造一個值 只知道有沒有，記不了附帶資料
慣例：參數收 &[T]，回傳給 Vec<T>。收的時候放寬，給的時候給完整所有權。字串版本是「參數收 &str，回傳給 String」。

速記片段

use std::collections::{BTreeMap, HashMap, HashSet, VecDeque};

// 去重／判斷看過沒
let mut seen: HashSet<&str> = HashSet::new();
seen.insert("apple");            // true  ← 第一次
seen.insert("apple");            // false ← 已存在
seen.contains("apple");          // true

// 有序的鍵值表（介面同 HashMap）
let mut b: BTreeMap<String, usize> = BTreeMap::new();
*b.entry(k).or_insert(0) += 1;
for (k, v) in &b { }             // 一定按鍵排序

// 兩端進出
let mut q: VecDeque<&str> = VecDeque::new();
q.push_back("b");
q.push_front("a");
q.pop_front();                   // Some("a")

// 量一個型別多大
use std::mem::size_of;
println!("{}", size_of::<Vec<i32>>());
