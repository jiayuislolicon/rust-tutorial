? 運算子與 From trait

? 運算子：失敗提早回傳，成功繼續

fn load_report(filename: &str) -> Result<Report, AppError> {
    let content = fs::read_to_string(filename)?;   // Err 就提早 return Err(...)
    if content.trim().is_empty() {
        Err(AppError::Empty)
    } else {
        Ok(Report::new(filename, content))
    }
}

expr?：Ok(v) 就變成 v，程式繼續；Err(e) 就讓整個函式立刻回傳 Err(e)。只能用在回傳 Result（或 Option）的函式裡。

型別不一樣時：impl From 教它怎麼轉

impl From<std::io::Error> for AppError {
    fn from(e: std::io::Error) -> AppError {
        AppError::ReadFailed(e)
    }
}

? 遇到 Err(e) 時會自動呼叫 AppError::from(e) 做轉換，再回傳。e 的型別跟函式的錯誤型別一樣時，這一步等於沒做事；不一樣時，沒有對應的 impl From 會編譯失敗：the trait `From<std::io::Error>` is not implemented for `AppError`。

不是所有 Err(...) 都需要 From——只有「用 ? 轉發別的函式的錯誤」才需要。自己判斷邏輯後直接寫的 Err(AppError::Empty)，本來就已經是目標型別，不用轉換，也不用 ?。
