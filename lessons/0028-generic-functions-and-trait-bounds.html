一個函式，服務所有型別：泛型與 trait bound

學習目標：你會寫一個對數字有效的函式，然後發現同一份邏輯換成文字就編譯失敗。你會學會為什麼，用一行程式碼修好它，並學會怎麼讀陌生程式碼裡那些角括號塞滿條件的函式簽名。

1. 這個函式簽名，你現在還讀不懂

去讀任何一份 Rust 文件或別人寫的函式庫，你遲早會撞到長這樣的簽名： 

fn largest<T: PartialOrd>(list: &[T]) -> &T

Lesson 24 你已經見過角括號裡的 <T>，知道它代表「這裡可以放任何型別」。但這次角括號裡多了一個冒號，後面還跟著一個陌生的名字：PartialOrd。這一課就是來拆這件事的 —— 讀完之後，你會知道這個冒號在把關什麼，也會知道少了它會發生什麼事。

2. Trait：貼在型別身上的技能貼紙

Trait（特徵）宣告一種能力。你可以先把它想成一張技能貼紙：貼紙本身只寫「你必須會做什麼」，不寫「你實際上怎麼做」。

例如，我們定義一張叫做 Summarize 的貼紙，要求擁有它的型別都必須提供一個 summary()： 

trait Summarize {
    fn summary(&self) -> String;
}

這裡的 trait 只是宣告能力。它是在說：「如果一個型別要實作 Summarize，那它就必須有一個 summary()，而且回傳 String。」但它還沒有告訴我們這個函式到底要做什麼。

接著假設我們有一個 Article： 

struct Article {
    title: String,
}

我們可以用 impl TraitName for TypeName，把這張貼紙真正貼到 Article 上，並補上它的實作： 

impl Summarize for Article {
    fn summary(&self) -> String {
        format!("文章：{}", self.title)
    }
}

現在 Article 就具備了 Summarize 這個能力，所以可以呼叫： 

let article = Article {
    title: String::from("Rust 入門"),
};

println!("{}", article.summary());
// 文章：Rust 入門

所以可以把這兩個東西分開記：

  • trait：定義「需要具備什麼能力」。
  • impl：定義「這個型別要怎麼實作這個能力」。

你可以把整個過程想成： 

trait Summarize
    ↓
「會這個能力的人，都必須有 summary()」
    ↓
impl Summarize for Article
    ↓
「Article 真的把 summary() 寫出來了」

你已經在 GLOSSARY.md 見過這個字，但還沒正式學過怎麼自己寫一個。它和 TypeScript 的 interface 很接近： 

// TypeScript
interface Summarize {
  summary(): string;
}

class Article implements Summarize {
  summary() {
    return "文章：Rust 入門";
  }
}

Rust 和 TypeScript 的寫法不同，但這裡可以先抓住同一個核心：先描述一個型別必須具備的能力，再由具體型別提供實作。

3. 你早就實作過 trait 了，只是沒人跟你說

打開你自己的 hello_cli/src/errors.rs： 

impl fmt::Display for AppError {
    fn fmt(&self, f: &mut fmt::Formatter) -> fmt::Result {
        match self {
            AppError::Empty => write!(f, "空檔案"),
            // ...
        }
    }
}

這行 impl fmt::Display for AppError，就是「幫 AppError 貼上 Display 這張貼紙」。你當初是照著格式抄下來的，好讓 println!("{}", error) 能動。現在你知道這個格式的名字了：impl TraitName for TypeName { 補上要求的函式 }。From<std::io::Error> 也是同一件事，只是換了一張貼紙。

4. 泛型函式：同一份邏輯，不同型別

假設你想寫一個函式，找出一堆數字裡最大的那個： 

fn largest(list: &[i32]) -> &i32 {
    let mut largest = &list[0];
    for item in list {
        if item > largest {
            largest = item;
        }
    }
    largest
}

這個函式能動。但如果你之後想對一串 &str 做一樣的事呢？邏輯完全一樣，只有型別不同。與其複製貼上一份幾乎一樣的函式，泛型讓你把型別也變成參數： 

fn largest<T>(list: &[T]) -> &T {
    let mut largest = &list[0];
    for item in list {
        if item > largest {
            largest = item;
        }
    }
    largest
}

跑 cargo build。編譯器會擋下你：

error[E0369]: binary operation `>` cannot be applied to type `&T`
 --> largest.rs:5:17
  |
5 |         if item > largest {
  |            ---- ^ ------- &T
  |            |
  |            &T
  |
help: consider restricting type parameter `T` with trait `PartialOrd`
  |
1 | fn largest<T: std::cmp::PartialOrd>(list: &[T]) -> &T {
  |             ++++++++++++++++++++++

光寫 <T>，你只跟編譯器承諾「這是某個型別」。編譯器沒辦法假設任何型別都能用 > 比較 —— 因為確實不是每個型別都能。一塊石頭跟一個檔案路徑，你要怎麼比？它甚至在錯誤訊息裡把修法直接寫給你了。

5. Trait bound：把「能被比較」寫進型別的要求裡

照著編譯器的建議，在角括號裡加上冒號和 trait 名稱：

🔴 修改前 —— 沒有要求任何能力
fn largest<T>(list: &[T]) -> &T {
🟢 修改後 —— 這個 T 必須能被比較大小
fn largest<T: PartialOrd>(list: &[T]) -> &T {

<T: PartialOrd> 讀作「對任何有 >/< 的型別 T」。這叫做 trait bound（trait 約束）：把泛型從「任何型別都行」限縮成「任何型別都行，只要它有這個能力」。同一份函式，現在對兩種完全不同的型別都能用： 

let numbers = vec![34, 50, 25, 100, 65];
println!("{}", largest(&numbers));        // 100

let words = vec!["rust", "cargo", "compiler"];
println!("{}", largest(&words));          // rust

數字用 > 比大小，字串用 > 比字典順序 —— 兩者都實作了 PartialOrd，所以同一份程式碼原封不動地服務了兩種型別。這跟 TypeScript 的 function largest<T extends Comparable>(list: T[]): T 是同一個概念，extends 子句就是 TypeScript 的 trait bound。

6. 為什麼這對閱讀陌生程式碼有幫助

你已經在用滿足某個 trait bound 的型別了，只是沒注意到。report.word_counts() 回傳的 BTreeMap<String, usize>，它的 key 型別背後要求 K: Ord —— 這就是為什麼 BTreeMap 一定會照 key 排序：排序這件事本身需要「能比大小」這個能力，而 trait bound 就是編譯器確認這件事的地方。

下次你在文件或別人的程式碼裡看到角括號，這樣拆解它：

片段意思
<T>任何型別，但只能移動、存放，不能比較或印出
<T: PartialOrd>任何能用 >/< 比較的型別
<T: Display>任何能用 {} 印出的型別
<T: Display + PartialOrd>同時要求兩種能力，用 + 疊加
💡 看到 error[E0599]: no method named ... found 或 error[E0369]: binary operation ... cannot be applied，先去找函式簽名上的 trait bound。十之八九是你手上的型別沒有滿足它。

這一課的成果
你寫了一個只對數字有效的函式，看著它換成文字時編譯失敗，然後用一個 trait bound 讓同一份程式碼同時服務兩種型別。你也認出了自己早就寫過的 trait 實作 —— impl Display for AppError，只是這次知道它的名字。

下次讀到陌生的函式簽名，角括號裡的冒號不再是噪音：它是那個型別為了被這個函式接受，必須擁有的能力清單。
