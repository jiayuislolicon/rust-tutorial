.collect() — 把 iterator 變成 collection

學習目標：上一課你用 .fold() 走過 iterator，一步一步累積出最終結果。但如果你要的結果是標準 collection——Vec、String、BTreeMap——有更短的路： .collect()。你會用它簡化現有程式碼，並寫一個依行別篩選內容的新方法。

1. 一行你早就寫過的程式碼

打開 hello_cli/src/main.rs，找到 --words 分支：

let counts = report.word_counts();
let mut pairs: Vec<(&String, &usize)> = counts.iter().collect();
pairs.retain(|pair| *pair.1 >= min);
pairs.sort_by(|a, b| b.1.cmp(a.1));

先看第二行。counts.iter() 產生一個 iterator，逐項走過 map 裡的 (&String, &usize) 配對。接著 .collect() 把整個 iterator 消耗掉，把每一項收進 Vec。

這跟 .fold() 做的事很像：消耗 iterator，產出一個最終值。差別在於，.fold() 要你自己寫累積邏輯；.collect() 則是說「我已經知道怎麼從元素組出 Vec（或 String、BTreeMap）——你只要告訴我要哪種容器就好」。

2. 為什麼 .collect() 一定要你指定型別

試著拿掉型別標注：

let mut pairs = counts.iter().collect();

編譯器會拒絕：

error[E0283]: type annotations needed
  |
  |     let mut pairs = counts.iter().collect();
  |         ^^^^^^^^^ cannot infer type
  |
  = note: multiple `impl`s satisfying `_: FromIterator<...>` found

同一個 iterator 可以收進 Vec、VecDeque、HashSet，或其他型別。編譯器猜不到你要哪一種，所以你得明確告訴它。

跟 .fold() 對照一下：那邊你傳入初始值——例如 LineStats { empty: 0, ... }——編譯器從那個值就知道累積器的型別。.collect() 沒有初始值可以推，因此必須在某處寫清楚目標型別。

3. Vec<_> — 指定容器，元素型別交給編譯器

你不必把元素型別從頭寫到尾。Vec<_> 的意思是「我要 Vec，元素型別你自己推」。編譯器能從 iterator 推斷元素型別，這樣就夠了：

🔴 修改前 —— 元素型別全部手寫
let mut pairs: Vec<(&String, &usize)> = counts.iter().collect();
🟢 修改後 —— 元素型別交給編譯器填
let mut pairs: Vec<_> = counts.iter().collect();

底線 _ 代表「這段我不想寫，你來推」。編譯器已經知道 counts.iter() 產出 (&String, &usize)，所以會把空白填上。結果完全一樣——少打幾個字，保證不變。

現在就在 main.rs 做這個改動，跑 cargo build——跟改之前一樣能編譯。

4. .filter().collect() — 寫一個新方法

目前如果你想列出檔案裡所有註解行，沒有直接的方法可以問。line_stats() 只告訴你有幾行，不告訴你是哪幾行。你得把篩選加計數的邏輯重寫一遍，但拿掉計數那部分。

.filter().collect() 用一條管線解決：先篩出你要的行，再把留下來的收進 Vec。在 report.rs 裡、line_count() 後面加上這個方法： 

pub fn lines_of_kind(&self, kind: LineKind) -> Vec<&str> {
    self.content
        .lines()
        .filter(|line| Report::classify_line(line) == kind)
        .collect()
}

逐步看一遍：

  • self.content.lines() — 產生 &str 的 iterator，一行一項。
  • .filter(|line| ...) — 只保留分類符合 kind 的行。== 能運作，是因為 LineKind 有 derive PartialEq（Lesson 30 學過）。
  • .collect() — 把篩完後的 &str 收進 Vec<&str>。這裡不需要型別標注，因為函式簽名上的回傳型別已經告訴編譯器要組出什麼。

加一個測試：

#[test]
fn lines_of_kind_filters_correctly() {
    let report = Report::new("test.txt", "code\n\n// comment\nmore code\n".to_string());
    let comments = report.lines_of_kind(LineKind::Comment);
    assert_eq!(comments, vec!["// comment"]);

    let code_lines = report.lines_of_kind(LineKind::Code);
    assert_eq!(code_lines, vec!["code", "more code"]);
}

跑 cargo test：

注意方法本體裡的 .collect() 不需要型別標注。編譯器看宣告的回傳型別 Vec<&str>，就知道 .collect() 該產出什麼。只要目標型別已經在別處寫清楚——回傳型別、函式參數、或帶標注的 let——編譯器就會拿它來推。

5. .collect() 能組的不只是 Vec

.collect() 適用於任何實作 FromIterator trait 的型別。你暫時不必深究這個 trait——只要知道幾個標準型別已經支援：

  • Vec<T> — 把元素收進可增長的清單。這是最常見的用法。
  • String — 把 char 或 &str 的 iterator 接成一段字串。 
    let greeting: String = vec!["Hello", " ", "world"].into_iter().collect();
// greeting == "Hello world"
  • BTreeMap<K, V> — 把配對收進 map。你現有的 word_counts() 用 for 迴圈，是因為計數邏輯需要 .entry().or_insert()。但如果 key-value 配對已經準備好，可以直接 collect 進去。

什麼時候用 .collect()、什麼時候用 .fold()？一個簡單原則：結果是標準 collection，而且每個元素對應 collection 裡的一項，就用 .collect()。如果需要自訂累積邏輯——例如在 struct 裡逐項加計數——.fold() 才是對的工具。
