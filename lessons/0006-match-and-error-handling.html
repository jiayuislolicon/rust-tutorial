match 與正式的錯誤處理

目標：能用 match 拆開 Result，讓程式在輸入錯誤時「妥善處理」而不是直接當掉。

上一課用 .expect(...) 先讓程式動起來 —— 代價是使用者只要打錯格式，程式就整個當掉。真正的 CLI 工具不該這樣：使用者打錯，應該印出友善訊息、讓他們重打，而不是崩潰。這一課補上這塊。

回顧：Result 長什麼樣子

Result 是一個枚舉（enum），只有兩種可能的形式（variant）： 

enum Result<T, E> {
    Ok(T),   // 成功，裡面裝著結果
    Err(E),  // 失敗，裡面裝著錯誤資訊
}

.parse() 回傳的就是這種型別 —— .expect(...) 其實是「如果是 Err，就當掉並印訊息；如果是 Ok，把裡面的值拿出來」的捷徑寫法。

用 match 自己拆開它

use std::io;

fn main() {
    println!("請輸入你的年齡：");

    let mut input = String::new();
    io::stdin().read_line(&mut input).expect("讀取輸入失敗");

    match input.trim().parse::<i32>() {
        Ok(age) => println!("明年你 {} 歲", age + 1),
        Err(_) => println!("這不是一個有效的數字，請重新執行程式並輸入數字。"),
    }
}
逐行拆解：
  • match 後面接一個表達式（這裡是 .parse::<i32>() 的結果），依它實際是哪個 variant 走不同分支。
  • Ok(age) => ...：如果是 Ok，把裡面裝的值取出來、綁定成 age，這一分支才能用。
  • Err(_) => ...：如果是 Err，_ 代表「這裡有一個值，但我不在乎裡面裝什麼」，直接印出自訂的錯誤訊息。
  • 兩個分支必須涵蓋所有可能 —— 少寫一個 variant，編譯器會直接報錯拒絕編譯。這跟 Lesson 3 的 if/else 表達式很像，但 match 更嚴格：它會幫你確認每一種可能都被處理到了。

結合迴圈：錯誤就重問一次

把 Lesson 4 的 loop 概念和這裡的 match 合起來，就能做到「打錯就重問，打對就往下走」：

use std::io;

fn main() {
    let age: i32 = loop {
        println!("請輸入你的年齡：");
        let mut input = String::new();
        io::stdin().read_line(&mut input).expect("讀取輸入失敗");

        match input.trim().parse() {
            Ok(n) => break n,
            Err(_) => println!("不是有效的數字，再試一次。"),
        }
    };

    println!("明年你 {} 歲", age + 1);
}

loop 是一個沒有結束條件、會無限重複的迴圈；break n 除了跳出迴圈，還把 n 當成整個 loop 表達式的值 —— 這跟 if/else 能當表達式是同一個道理。打錯的話沒有 break，就會回到迴圈開頭再問一次。

這一課的成果
你現在能用 match 拆開 Result，分別處理成功跟失敗，也能結合 loop + break 做到「打錯就重問」。把前六課全部串起來，你已經能寫一個會跟使用者互動、輸入錯誤不會崩潰的小工具了 —— 這是你能力範圍內第一個「像樣」的 CLI 程式雛形。
