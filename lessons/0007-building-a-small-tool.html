Lesson 0007 · Rust · CLI 工具養成路線

整合一個小工具

目標：把前六課的東西全部串起來，寫一個能重複使用、輸入錯誤不會崩潰的攝氏轉華氏小工具。

前六課分別學了：函式（Lesson 3）、迴圈與 Vec（Lesson 4）、讀取輸入（Lesson 5）、match 與錯誤處理（Lesson 6）。這一課不教新的大觀念，而是把它們接成一個完整程式 —— 這正是實際寫 CLI 工具時的樣子：沒有哪一課的內容是孤立的。

完整程式：攝氏轉華氏

use std::io;

fn celsius_to_fahrenheit(c: f64) -> f64 {
    c * 9.0 / 5.0 + 32.0
}

fn main() {
    let mut history: Vec<f64> = Vec::new();

    loop {
        println!("輸入攝氏溫度（輸入 q 結束）：");
        let mut input = String::new();
        io::stdin().read_line(&mut input).expect("讀取輸入失敗");
        let input = input.trim();

        if input == "q" {
            break;
        }

        match input.parse::<f64>() {
            Ok(c) => {
                let f = celsius_to_fahrenheit(c);
                println!("{:.1}°C = {:.1}°F", c, f);
                history.push(c);
            }
            Err(_) => println!("不是有效的數字，再試一次。"),
        }
    }

    println!("這次總共轉換了 {} 筆：{:?}", history.len(), history);
}
對照前幾課，這裡沒有一行是新概念：
  • fn celsius_to_fahrenheit(c: f64) -> f64 —— Lesson 3 的函式，帶參數、帶回傳值，最後一行沒分號。
  • let mut history: Vec<f64> = Vec::new(); 加 history.push(c) —— Lesson 4 的 Vec，動態收集每次輸入的溫度。
  • io::stdin().read_line(&mut input)、.trim()、.parse() —— Lesson 5 的輸入讀取與轉換。
  • loop { ... match ... } —— Lesson 6 的「打錯就重問」模式，這裡用 if input == "q" { break; } 讓使用者可以主動結束。
兩個小新東西，但都很小： f64 是浮點數型別（可以有小數點），跟之前一直用的整數 i32 對應；{:.1} 是格式化寫法，代表「小數點後留 1 位」。{:?}（Debug 格式）能直接印出 Vec 這種複合資料的內容，方便除錯或做總結輸出 —— 一般 {} 沒辦法直接印一整個 Vec。

為什麼這樣組織？

把「轉換邏輯」抽成 celsius_to_fahrenheit 這個獨立函式，而不是直接寫在 main 裡，有一個實際好處：以後想加測試（之後會教），或想在別的地方重複使用這個轉換，直接呼叫函式就好，不用把 main 的迴圈跟輸入邏輯也搬過去。把「純計算」跟「跟使用者互動」分開，是組織 CLI 工具的基本原則。

小測驗：如果使用者在還沒輸入 q 之前，中間有一次打錯（例如打了 "abc"），history 最後會不會把這次錯誤也記進去？（用 3 個字回答，例如「不會記」或「會記錄」這種長度）
這一課的成果
你現在有一個完整、能重複使用、輸入錯誤不會崩潰的 CLI 小工具，而且清楚知道裡面每一行分別是哪一課教的。這是你目前所有 Rust 知識的第一次「整合測試」—— 下一課會開始碰真正需要處理錯誤細節、而不只是重試的情境（例如命令列參數、檔案讀寫）。
