Lesson 0025 · Rust · CLI 工具養成路線

閉包：把「怎麼做」當成值傳出去

學習目標：看懂 |x| ... 這種寫法在做什麼，知道它跟一般函式的唯一關鍵差別，並且能自己寫一個傳給 sort_by 的閉包。學完你也會知道 Fn / FnMut / FnOnce 出現在簽名裡時該怎麼讀。

1. 你會卡在哪：一般函式是「密室」

上一課你把 word_counts 換成了 BTreeMap，輸出變成照字母排序。現在你想改需求： 照出現次數由多到少排，而且只留下出現至少 2 次的字。

BTreeMap 幫不上忙，因為它只會照「鍵」（字母）排，而你要照「值」（次數）排。

所以你回到 Vec，然後發現 sort() 也不夠用 —— 它只有一種排法（從小到大）。你需要一個能讓你 指定怎麼比的工具。同理，要濾掉次數太少的字，你需要一個能讓你 指定怎麼判斷的方法。

你可能會想：「那就寫個函式傳進去吧！」於是你寫出這樣的程式碼： 

fn main() {
    let min = 2;

    fn keep(n: &i32) -> bool {
        *n >= min          // ← 想讀外面的 min，但編譯器會報錯！
    }

    let nums = vec![1, 2, 3];
    let kept: Vec<&i32> = nums.iter().filter(|n| keep(n)).collect();
    println!("{:?}", kept);
}

編譯器會無情地擋下你：

error[E0434]: can't capture dynamic environment in a fn item
 --> src/main.rs:5:15
  |
5 |         *n >= min
  |               ^^^
  |
  = help: use the `|| { ... }` closure form instead

這就是卡點：在 Rust 裡，一般的 fn 函式就像一間「密室」，它完全看不到外面的區域變數。不管你把 fn 寫在哪裡，哪怕是寫在 main 裡面，它也讀不到旁邊的 min。

但編譯器很貼心地給了提示：use the `|| { ... }` closure form instead（改用閉包寫法）。這一課，我們就要來拆解這個神奇的工具。

2. 你其實已經在用它了

回頭看看你自己的 report.rs，裡面有這一行：

.filter(|line| matches!(Report::classify_line(line), LineKind::Empty))

裡面的 |line| ... 就是閉包。其實你從 Lesson 20 開始就一直在寫閉包了，只是還沒有人正式向你介紹它。

把語法拆開來看，它只有三個部分：

|line|    matches!(...)
└─┬──┘    └────┬─────┘
  │            └── 主體：算出來的值就是回傳值
  └── 參數，夾在兩根直線（Pipe）中間

你對這個形狀應該不陌生，只是括號長得不太一樣。TypeScript 的箭頭函式（Arrow Function）其實就是同一件事：

TypeScript

const inc = (x: number): number => { return x + 1; };
const inc = (x: number) => x + 1;
const inc = (x) => x + 1;

Rust

let inc = |x: i32| -> i32 { x + 1 };
let inc = |x: i32| x + 1;
let inc = |x| x + 1;

參數的型別和回傳型別通常都可以省略。這一點跟一般函式很不一樣 —— fn 的每個參數都必須標明型別，沒得商量。閉包可以省，是因為它通常只在附近被用到，編譯器看得到呼叫端，能自己推斷出來。

💡 閉包的型別只會被推斷一次。你寫 let f = |x| x + 1; 之後，第一次拿它來算 f(1) 時，x 就被定死成 i32 了。之後如果再傳 f(1.5) 就會編譯失敗。它不是泛型，只是省略標註而已。

3. 閉包到底是什麼：自帶「百寶袋」的函式

一句話總結：閉包就是一個函式，外加它從周圍「偷偷打包帶走」的變數。

這個「打包帶走」的動作，在程式語言裡有個專有名詞叫捕捉環境（capture the environment）。第 1 節那個錯誤訊息裡的 capture dynamic environment 講的就是這件事。

如果我們把第 1 節的 fn 換成閉包，同樣的程式就能順利執行：

fn main() {
    let min = 2;
    let nums = vec![1, 2, 3];

    // 這裡的 |n| **n >= min 就是閉包
    let kept: Vec<&i32> = nums.iter().filter(|n| **n >= min).collect();
    println!("{:?}", kept);   // [2, 3]
}

差別只有一個：閉包記得 min 的存在。這是它存在的最大價值。其他你能用一般函式做的事，閉包也都能做。

這也解釋了為什麼 filter、map、sort_by 這些方法，要求的參數都是閉包而不是函式。因為它們要讓你把「判斷條件」當成一個值傳進去，而這個條件通常會需要用到你手邊的變數（例如 min）。

4. Fn、FnMut、FnOnce 怎麼讀：閉包對變數的「態度」

既然閉包會把外面的變數抓進來，那就衍生出一個新問題：抓進來之後，它打算對這些變數做什麼？

這其實就是 Lesson 10 借用規則的延伸。答案只有三種，Rust 給了它們三個專屬的名字：

名字 對變數的態度 對應的借用方式 可以呼叫幾次
Fn 「只看不摸」（唯讀） &T 無限次
FnMut 「借來改一下」（會修改） &mut T 無限次
FnOnce 「有借無還」（消耗掉） 取得所有權 (Ownership) 只能一次

放心，你不需要手動宣告你的閉包是哪一種。編譯器非常聰明，它會看你在閉包裡怎麼使用那些變數，自動幫你分類。這三個名字通常只會在你閱讀官方文件或函式簽名時出現。

來看看 FnMut 的例子 —— 閉包修改了外面的 total：

fn main() {
    let mut total = 0;
    let mut add = |x: i32| total += x;   // ← 因為改了外面的變數，編譯器判定它是 FnMut

    add(1);
    add(2);
    println!("{}", total);   // 3
}

注意 let mut add：連閉包這個變數本身都要標示 mut，因為呼叫它會改到它肚子裡存的那個 &mut total。

至於 FnOnce，顧名思義就是「呼叫一次就沒了」。這種閉包會把捕捉到的值直接交出去：

fn main() {
    let owned = String::from("hi");
    let consume = move || owned;    // ← 把 owned 的所有權交出去了

    println!("{}", consume());
    println!("{}", consume());      // ← 第二次呼叫會報錯！
}
error[E0382]: use of moved value: `consume`
  |
4 |     println!("{}", consume());
  |                    --------- `consume` moved due to this call
5 |     println!("{}", consume());
  |                    ^^^^^^^ value used here after move

編譯器會告訴你：closure cannot be invoked more than once because it moves the variable out of its environment。因為它把 owned 送走了，第二次呼叫時已經沒有東西可以送了，所以只能呼叫一次（Once）。

5. move：強迫「連根拔起」帶走

上一段的程式碼出現了 move ||。這個關鍵字的作用是：強迫閉包取得它用到的每個變數的「所有權」，而不是只用借的。

預設情況下，閉包很客氣，會盡量用「借」的 —— 能只讀就只讀（&），需要改才借（&mut）。但加了 move 之後，閉包就會變得霸道，直接把變數整個搬進自己肚子裡。

為什麼會需要這麼霸道？回想一下 Lesson 10：借用是有期限的。如果閉包活得比它借的東西還要久，借用就不成立了。

最常見的場景是把閉包丟到另一條執行緒（Thread）上跑 —— 原本的函式可能早就執行完畢、變數都被清除了，但另一條執行緒上的閉包還在跑。這時候如果只用借的，就會讀到無效的記憶體。所以必須用 move 把變數整個搬進閉包裡帶走。

目前你不需要主動寫 move。這一課特別提出來，是因為你在看別人的 code 時一定會遇到它（尤其是 thread::spawn(move || ...) 和各種非同步 Async 的寫法）。看到它時你只要知道：「喔！這個閉包把東西吃進去了，外面的世界不能再用這個變數了。」

6. 簽名裡的閉包長什麼樣：串聯上一課的「大小」概念

現在來讀真正會卡住你的東西。當一個函式要收閉包當參數時，它的參數型別會長得有點嚇人： 

fn count_if(text: &str, test: impl Fn(&str) -> bool) -> usize {
    text.lines().filter(|line| test(line)).count()
}

我們把 impl Fn(&str) -> bool 一段一段拆解：

  • impl：「隨便什麼型別都行，只要它符合後面的條件」。
  • Fn：「這個東西要能被當成函式呼叫，而且對捕捉到的變數『只看不摸』」。
  • (&str)：「呼叫它的時候，要傳一個 &str 進去」。
  • -> bool：「它執行完會回傳 bool」。

整句話翻譯成人話就是：「給我任何一個吃 &str、吐 bool、而且不會亂改東西的可呼叫物。」

用起來就像這樣：

let text = "code\n\n// comment\n";

println!("{}", count_if(text, |line| line.trim().is_empty()));   // 1
println!("{}", count_if(text, |line| line.starts_with("//")));   // 1

count_if 負責「怎麼跑迴圈」，呼叫端負責「怎麼判斷」。這就是把行為當成值傳出去的實際應用 —— 也正好可以拿來簡化你 count_kinds 裡那三段幾乎一樣的程式碼。

另一種你會看到的寫法是 Box<dyn Fn(&str) -> bool>：

寫法 意思 什麼時候用
impl Fn(...) 某一個特定的閉包型別，編譯期就決定好 放在函式參數位置，最常見
Box<dyn Fn(...)> 放在堆積 (Heap) 上的閉包，執行期才知道是哪一個 要存進 struct、或放進 Vec 裡時

還記得 Lesson 24 提到的「編譯器需要知道你要佔多大位子」嗎？每個閉包在底層都是一個編譯器偷偷生成的、獨一無二的型別，因為它們捕捉的變數數量和大小各不相同，所以每一個閉包的大小都不一樣。

如果你要把不同大小的閉包放進同一個 Vec 裡，編譯器算不出大小就會罷工。這時候就得用 Box 包一層指標，把它變成固定大小（8 位元組）。至於 dyn（Dynamic Dispatch）的詳細機制，我們會在 Lesson 30 深入探討。

7. 練習一：讓編譯器把錯誤講給你聽

新開一個檔案（或用你的 types.rs 那種暫存檔），把第 1 節那段會失敗的程式碼完整打一次： 

fn main() {
    let min = 2;

    fn keep(n: &i32) -> bool {
        *n >= min
    }

    let nums = vec![1, 2, 3];
    let kept: Vec<&i32> = nums.iter().filter(|n| keep(n)).collect();
    println!("{:?}", kept);
}

跑起來，親眼看看編譯器抱怨 can't capture dynamic environment in a fn item。然後照著編譯器的建議改：把 keep 整個刪掉，直接在 filter 裡寫閉包。

成功條件：輸出 [2, 3]。

💡 改完之後試著把 let min = 2; 改成 3，確認輸出跟著變成 [3]。這是在驗證「閉包真的讀到了外面的變數」，不是碰巧算對。

8. 練習二：把 --words 改成按次數排序

回到 hello_cli。打開 src/main.rs，找到 --words 那一段：

if words_count_only {
    let counts = report.word_counts();
    for (word, count) in counts {
        println!("{} {}", word, count);
    }

    return Ok(());
}

改成這樣：

if words_count_only {
    let counts = report.word_counts();

    let min = 2;
    let mut pairs: Vec<(&String, &usize)> = counts.iter().collect();
    pairs.retain(|pair| *pair.1 >= min);
    pairs.sort_by(|a, b| b.1.cmp(a.1));

    for (word, count) in pairs {
        println!("{} {}", word, count);
    }

    return Ok(());
}

這裡出現了三個新東西，每一個都跟閉包有關：

  • retain：就地刪掉不符合條件的元素。它的閉包捕捉了外面的 min —— 這就是第 1 節那個一般函式辦不到的事，現在成功在你的程式裡運作了。
  • sort_by：你告訴它怎麼比大小。pair.1 是次數，寫成 b.1.cmp(a.1) 就是拿後面的比前面的，也就是由大排到小。
  • *pair.1：pair.1 的型別是 &usize，要跟數字 2 比大小得先用 * 解開（Dereference）。如果你忘了寫，編譯器會說 expected `&usize`, found integer，並且直接把 * 該補在哪裡畫給你看（help: consider dereferencing the borrow）。

成功條件：

指令 應該看到
cargo run -- --words words.txt apple 3 然後 banana 2（cherry 只出現 1 次，被濾掉了）
cargo test 5 個測試全過，而且你一個字都不用改
順帶回答上一課留的伏筆。Lesson 24 讓你刪掉 collect + sort，當時說「要照值排的時候還是得用回來」。這就是那個時候。BTreeMap 負責照鍵排，Vec + sort_by 負責照其他任何東西排 —— 兩個都要會，看需求選。
這一課的成果
你會讀也會寫 |x| ... 了，而且知道它跟 fn 的差別只有一件事：閉包記得它周圍的變數。

這件事解鎖的是一整類函式 —— filter、map、sort_by、retain、find 都是收閉包的。以後在標準庫文件裡看到參數寫 F: FnMut(&T) -> bool，你知道那只是在說「傳一個判斷式進來」。
