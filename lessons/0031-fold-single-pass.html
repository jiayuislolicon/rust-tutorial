Lesson 0031 · Rust · CLI 工具養成路線

三次變一次：用 .fold() 累加結果

學習目標：你的 line_stats() 對同一份文字掃了三遍，每遍只數一種行。你會用 .fold() 把它改成一次走完——邊走邊把計數累加進 LineStats 裡。

1. 同一條路，走了三遍

打開 hello_cli/src/report.rs，找到 line_stats()： 

pub fn line_stats(&self) -> LineStats {
    let empty = self.content.lines()
        .filter(|line| matches!(Report::classify_line(line), LineKind::Empty))
        .count();

    let comment = self.content.lines()
        .filter(|line| matches!(Report::classify_line(line), LineKind::Comment))
        .count();

    let code = self.content.lines()
        .filter(|line| matches!(Report::classify_line(line), LineKind::Code))
        .count();

    LineStats { empty, comment, code }
}

三段程式碼的結構完全一樣：取得所有行、過濾出一種、數有幾個。差別只在 matches! 裡比對的是哪個 LineKind。每一段都呼叫了 .lines()，所以同一份文字被從頭到尾掃了三遍。

LineKind 只有三個 variant，掃三遍在效能上幾乎感覺不出來。但問題出在結構上：三段幾乎一模一樣的程式碼，以後要改就得改三次。如果再加一種行——比如 LineKind::DocComment——你得複製第四段，然後在 LineStats 加一個欄位。漏掉任何一步，編譯器不一定會提醒你。

更自然的做法是：走一遍，每看到一行就判斷它是什麼，把對應的計數器加 1。這正是 .fold() 在做的事。

2. .fold()：帶一個袋子走完整段路

上一節說要走一遍——.fold() 就是讓你邊走邊累加的工具。你可以把它想成帶著一個袋子從頭走到尾；在 API 裡，那個袋子叫做累加器。

你已經用過 .filter()、.map()、.count()——它們各自只做一件事。.fold() 則把動作交給你決定： 

iterator.fold(初始值, |累加器, 元素| {
    // 用元素更新累加器
    累加器
})

兩個參數：

  1. 初始值——你帶著出發的累加器。可以是一個數字（從 0 開始加）、一個 struct（欄位全部歸零）、甚至一個 Vec。型別由你決定。
  2. 一個 closure——每走一步，.fold() 把目前的累加器和當前元素一起交給它。closure 處理完之後，必須把累加器交回來，下一步才能繼續用。

走完全部元素之後，.fold() 把最終的累加器當作回傳值。跟 .count() 一樣，它是消耗性的方法——呼叫之後疊代器就沒了。

先用一個最小的例子：

let total = [1, 2, 3].iter().fold(0, |acc, n| acc + n);
// total == 6

初始值是 0。第一步 0 + 1 = 1，第二步 1 + 2 = 3，第三步 3 + 3 = 6。走完，回傳 6。

如果你用過 JavaScript 的 Array.prototype.reduce()，.fold() 就是同一件事——只是 Rust 總是要求你明確給初始值，沒有「用第一個元素當初始值」的省略寫法。

3. 把 line_stats() 改成一次走完

現在把累加器換成 LineStats——三個欄位都從 0 開始。每看到一行，用 classify_line 判斷它是哪一種，然後把對應的計數器加 1：

🔴 修改前 —— 三次 .lines()，三次 .filter().count()
pub fn line_stats(&self) -> LineStats {
    let empty = self.content.lines()
        .filter(|line| matches!(Report::classify_line(line), LineKind::Empty))
        .count();

    let comment = self.content.lines()
        .filter(|line| matches!(Report::classify_line(line), LineKind::Comment))
        .count();

    let code = self.content.lines()
        .filter(|line| matches!(Report::classify_line(line), LineKind::Code))
        .count();

    LineStats { empty, comment, code }
}
🟢 修改後 —— 一次 .lines()，一次 .fold()
pub fn line_stats(&self) -> LineStats {
    self.content.lines().fold(
        LineStats { empty: 0, comment: 0, code: 0 },
        |mut acc, line| {
            match Report::classify_line(line) {
                LineKind::Empty => acc.empty += 1,
                LineKind::Comment => acc.comment += 1,
                LineKind::Code => acc.code += 1,
            }
            acc
        },
    )
}

逐行來看這個 closure：

  • |mut acc, line|——兩個參數。acc 是累加器，型別是 LineStats；line 是當前這一行。mut 寫在 acc 前面，因為你要修改它的欄位。
  • match Report::classify_line(line)——Lesson 30 之前你就有這個函式了，它回傳 LineKind。match 把三個 variant 各自對應到一個 += 1。
  • 最後一行 acc——把更新過的累加器交回去，.fold() 才能帶著它走下一步。少了這行，closure 的回傳型別就不是 LineStats，編譯器會報錯。

4. mut acc 不是 &mut

注意 closure 參數寫的是 mut acc，不是 &mut acc。這裡的 mut 跟你寫 let mut x = 5; 是同一回事：宣告這個區域變數可以被修改。.fold() 在每一步都把累加器的所有權交給 closure，closure 改完之後再把所有權交回去。整個過程沒有借用，只有 move 進來、move 出去。

如果你把 mut 拿掉，編譯器會報錯：

error[E0594]: cannot assign to `acc.empty`, as `acc` is not declared as mutable
  |
  |         |acc, line| {
  |          --- help: consider changing this to be mutable: `mut acc`

跟 let x = 5; x += 1; 失敗是同一個道理。closure 的參數就是區域變數，寫不寫 mut 決定你能不能改它。

六個測試全過。行為沒有任何改變——你改的是實作方式，不是結果。這正是 Lesson 30 加上 LineStats 和 assert_eq! 之後帶來的保障：只要測試還是綠的，你可以放心重寫裡面的邏輯。

6. .fold() 的型別怎麼推導

你沒有在任何地方標註 acc 或 line 的型別，但編譯器全都知道。推導的鏈條是這樣的：

  1. 初始值是 LineStats { empty: 0, ... }，所以累加器的型別是 LineStats。
  2. .lines() 產生 &str，所以 line 是 &str。
  3. .fold() 的回傳型別等於累加器的型別，也就是 LineStats——剛好是函式簽名裡宣告的回傳型別。

這跟你在 Lesson 25 學到的 closure 型別推導是同一件事：編譯器看呼叫的上下文，就能確定每個參數和回傳值的型別。你不需要寫出來，但你要能在腦中追得出來。

7. 什麼時候用 .fold()，什麼時候不用

.fold() 的強項是把多件事合併成一次走完。如果你只是要做一件事——過濾、計數、轉換——用 .filter()、.count()、.map() 更直接。它們各自只做一個動作，一眼就知道發生了什麼。

該用 .fold() 的訊號通常是：你發現自己對同一個疊代器寫了好幾段 .filter().count() 或 .filter().map().collect()，每段只在條件上不同。這時候合併成一次 .fold()，既減少重複，也確保所有計數在同一次遍歷中完成。

你把三段結構相同的 .filter().count() 合併成一個 .fold()，一次走完所有行。你學到了 .fold() 需要一個初始值和一個 closure——每一步 closure 都拿到累加器和當前元素，處理完之後要把累加器交回來。
