Lesson 0037 · Rust · CLI 工具養成路線

外部 Crate —— 你的第一個 Cargo 依賴

學習目標： 到目前為止，你的工具只用過標準函式庫（std）。這一課要走出 std 的世界：從 crates.io 拉進第一個外部依賴 clap，把手寫了六課的參數解析器，換成用一個 struct 加 derive 就能描述完畢的寫法。

1. 二十行的 match 與一個老問題

打開 main.rs，看看 run() 裡那段 while let 配上 match 的程式碼： 

while let Some(arg) = args.next() {
    match arg.as_str() {
        "--count-only" => count_only = true,
        "--words"      => words_count_only = true,
        "--min"        => match args.next() { ... },
        "--format"     => match args.next() { ... },
        "--grep"       => match args.next() { ... },
        _ if arg.starts_with("-") => return Err(...),
        _ => filename = Some(arg),
    }
}

每加一個旗標，就多一個 match 分支、多一個變數、多一段「後面少了值」的錯誤處理。使用者打 --help 也看不到任何說明——因為你從來沒實作過它。

參數解析是被解決了幾十年的老問題。Rust 社群早就有成熟的 crate 可以用，這件事不需要自己從頭寫。

2. Rust 的套件生態系：crates.io

到目前為止，你用過的每一個型別和函式——String、Vec、HashMap、fs::read_to_string——都來自 Rust 的標準函式庫（std）。它隨 Rust 一起安裝，不需要額外下載。

Rust 生態系裡還有數以萬計的外部 crate，全部集中在一個叫 crates.io 的公開登錄處（registry）。任何人都可以把自己寫的 library 發佈上去，任何人也都可以拉下來用。 

std         →  Rust 內建的，什麼都不用裝
crates.io   →  社群維護的，cargo 會幫你下載

3. cargo add：加入一個依賴

第一個要加的外部 crate 是 clap——Rust 生態系裡最廣泛使用的命令列參數解析器。在 hello_cli/ 目錄裡執行： 

cargo add clap --features derive

這一行做了兩件事：

  1. 從 crates.io 查出 clap 目前的最新版本。
  2. 在 Cargo.toml 的 [dependencies] 區段加上一行。

打開 Cargo.toml，你會看到它變成：

[dependencies]
clap = { version = "4", features = ["derive"] }

version = "4" 是語意版本（semver）——代表「4.x.y 都可以，只要 API 不破壞性改變就行」。 features = ["derive"] 則開啟了 clap 的一個可選功能：讓你用 #[derive(Parser)] 定義參數，而不是比較囉嗦的 builder API。

💡 什麼是 feature？ Rust 的 crate 可以把某些功能放在 feature flag 後面；沒有開啟的 feature 不會被編譯，可以減少編譯時間和二進位檔大小。 clap 的 derive feature 需要額外的程序巨集（proc-macro）機制，所以它是可選的。

4. docs.rs：怎麼讀外部 crate 的文件

加入依賴之後，你會需要讀它的文件。每一個發佈到 crates.io 的 crate，都會自動在 docs.rs 產生 API 文件。格式和 std 的官方文件一模一樣——因為用的是同一個工具（rustdoc）。

要看 clap 的文件，直接打開：

https://docs.rs/clap

docs.rs 是你和外部 crate 打交道時最常開的頁面。搜尋 struct、翻範例、看 method 簽名——你在 std 文件裡做的每一件事，在 docs.rs 上操作方式完全相同。

5. 用 clap 重寫參數解析

重寫從 import 開始。先在 main.rs 最上方加上：

use clap::Parser;

然後定義一個 struct 來描述你的命令列介面：

/// 分析原始碼檔案的小工具
#[derive(Parser)]
struct Cli {
    /// 要分析的檔案
    filename: Option<String>,

    /// 只印行數摘要
    #[arg(long)]
    count_only: bool,

    /// 只印詞頻統計
    #[arg(long)]
    words: bool,

    /// 詞頻篩選門檻
    #[arg(long, default_value_t = 1)]
    min: usize,

    /// 輸出格式 (plain / json)
    #[arg(long, default_value = "plain")]
    format: String,

    /// 搜尋包含此關鍵字的行
    #[arg(long)]
    grep: Option<String>,
}

每個欄位都直接對應一個命令列參數。下面幾個重點值得記一下：

  • #[derive(Parser)] 讓 clap 幫你產生解析程式碼——概念和你用 #[derive(Debug)] 讓編譯器產生 debug 格式化一樣。
  • /// 文件註解會自動變成 --help 裡的說明文字。
  • Option<String> 代表這個參數可以不給——clap 看到 Option 就知道它是可選的。
  • bool 代表開關型旗標——有給就是 true，沒給就是 false。
  • #[arg(long)] 表示這是 -- 開頭的長旗標。欄位名的底線會自動轉成連字號：count_only → --count-only。
  • default_value_t = 1 直接給目標型別的值作為預設值。另一個寫法是 default_value = "plain"，給的是字串，clap 會在執行時把它 parse 成目標型別。簡單記法：值本身是字串就用 default_value，值是數字或其他型別就用 default_value_t。

定義好 struct 之後，run() 只需要一行就能拿到所有參數： 

fn run() -> Result<(), AppError> {
    let cli = Cli::parse();

    let formatter = make_formatter(&cli.format)
        .ok_or_else(|| AppError::UnknownFlag(format!("--format {}", cli.format)))?;

    let filename = match cli.filename {
        Some(name) => name,
        None => {
            println!("用法：hello_cli [OPTIONS] <檔名>");
            return Ok(());
        }
    };

    let report = load_report(&filename)?;

    if let Some(ref pattern) = cli.grep {
        for line in report.matching_lines(pattern) {
            println!("{}", line);
        }
        return Ok(());
    }

    if cli.words {
        let counts = report.word_counts();
        let mut pairs: Vec<_> = counts.iter().collect();
        pairs.retain(|pair| *pair.1 >= cli.min);
        pairs.sort_by(|a, b| b.1.cmp(a.1));
        for (word, count) in pairs {
            println!("{}: {}", word, count);
        }
        return Ok(());
    }

    if cli.count_only {
        println!("{}", report.summary());
    } else {
        println!("{}", formatter.format_report(&report));
    }

    Ok(())
}

整段 while let + match 消失了。 Cli::parse() 一行讀完所有參數、驗證格式、印出錯誤訊息。之後你只需要讀 cli 的欄位，就像讀一個普通 struct 一樣。

6. 你的工具現在免費送了 --help

試試看：

cargo run -- --help
分析原始碼檔案的小工具

Usage: hello_cli [OPTIONS] [FILENAME]

Arguments:
  [FILENAME]  要分析的檔案

Options:
      --count-only           只印行數摘要
      --words                只印詞頻統計
      --min <MIN>            詞頻篩選門檻 [default: 1]
      --format <FORMAT>      輸出格式 (plain / json) [default: plain]
      --grep <GREP>          搜尋包含此關鍵字的行
  -h, --help                 Print help

clap 從你的 struct 定義自動產生了完整的 help 頁面。 /// 寫的文件註解變成了說明文字，Option 讓參數顯示為可選，default_value 也標出來了——你完全不需要手動拼字串。

試試給一個不存在的旗標：

cargo run -- --oops file.txt
error: unexpected argument '--oops' found

Usage: hello_cli [OPTIONS] [FILENAME]

For more information, try '--help'.

以前你要自己寫 AppError::UnknownFlag 來處理這種情況。現在 clap 在你的程式碼跑到 run() 之前就已經把它攔下來了。

7. 比較前後

🔴 手寫解析——20 行 match + 7 個變數
let mut filename: Option<String> = None;
let mut count_only: bool = false;
let mut words_count_only: bool = false;
let mut min: usize = 1;
let mut format = String::from("plain");
let mut grep: Option<String> = None;

while let Some(arg) = args.next() {
    match arg.as_str() {
        "--count-only" => count_only = true,
        "--words"      => words_count_only = true,
        "--min"        => match args.next() { ... },
        "--format"     => match args.next() { ... },
        "--grep"       => match args.next() { ... },
        _ if arg.starts_with("-") => return Err(...),
        _ => filename = Some(arg),
    }
}
🟢 clap derive——一個 struct + 一行 parse
#[derive(Parser)]
struct Cli {
    filename: Option<String>,
    #[arg(long)] count_only: bool,
    #[arg(long)] words: bool,
    #[arg(long, default_value_t = 1)] min: usize,
    #[arg(long, default_value = "plain")] format: String,
    #[arg(long)] grep: Option<String>,
}

let cli = Cli::parse();

手寫版不是「錯的」——過去幾課你藉著它學會了 while let、match、Result 回傳。概念內化之後，就可以把重複的苦工交給專門的 crate，把注意力放在工具本身的邏輯上。

8. Cargo.lock

跑完 cargo add 之後，你的專案裡多了一個 Cargo.lock 檔案（如果之前沒有依賴，這是第一次出現）。它記錄了 clap 以及 clap 自己依賴的所有 crate 的精確版本號。

可以把這兩個檔案想成不同的精度：Cargo.toml 寫的是「我想要 4.x.y」；Cargo.lock 寫的是「我這次編譯用的是 4.5.23」。下次你（或別人）再跑 cargo build，Cargo 會讀 Cargo.lock 確保用的是同一個版本，不會悄悄升級。

對二進位 crate（也就是你正在寫的工具），Cargo.lock 應該提交到版本控制。這樣任何人 clone 你的 repo 之後，編譯出來的東西會跟你的一模一樣。

9. 什麼時候該找 crate？什麼時候自己寫？

沒有硬性規則，但下面幾個問題可以幫你判斷：

考量 自己寫 找 crate
你正在學習這個概念 ✓
這是一個被解決了很多年的問題 ✓
你的需求很簡單，三五行就搞定 ✓
你不想自己維護各種邊界案例的測試 ✓
安全性很重要（加密、TLS） ✓

前面手寫參數解析器，是因為那幾課的重點是 match、while let、Result。概念學會了，就可以把這塊換成社群維護了十幾年的 crate。

10. 動手做

照下面五步做一遍：

  1. 在 hello_cli/ 目錄執行 cargo add clap --features derive。
  2. 在 main.rs 定義 Cli struct，用 #[derive(Parser)]。
  3. 把 run() 裡的手寫解析迴圈換成 Cli::parse()，用 cli.欄位名 取代原本的區域變數。
  4. 跑 cargo test 確認原有測試仍然通過。
  5. 跑 cargo run -- --help 確認你的工具現在有完整的說明頁面。
💡 換完解析邏輯之後，use std::env; 可以拿掉了——那是手寫版才需要的。但 report.rs 和 formatter.rs 完全不需要改。
