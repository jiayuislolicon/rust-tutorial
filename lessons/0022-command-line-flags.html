Lesson 0022 · Rust · CLI 工具養成路線

命令列選項：解析 flag

學習目標：讓 hello_cli 除了檔名之外，還能接受一個選項 --count-only。你會學到 skip(1)、match arg.as_str()、以及 match 的守衛（guard）寫法。

1. 目前的參數處理有一個限制

現在 run() 是這樣拿檔名的： 

let args: Vec<String> = env::args().collect();

let filename = match args.get(1) {
    Some(name) => name,
    None => { /* 印用法 */ }
};

這段程式碼假設「第 1 個參數就是檔名」。位置決定意義。

真實的 CLI 工具不是這樣運作的。使用者會打 tool --count-only notes.txt，也會打 tool notes.txt --count-only。兩種都該正常運作。

所以參數不能靠位置來認，要靠內容來認。這一課要做的事就是：走過每一個參數，判斷它是選項還是檔名。

2. skip(1)：跳過程式名稱

env::args() 的第 0 個元素是程式自己的路徑，不是使用者輸入的參數。

它回傳的是一個疊代器（上一課學的）。所以要跳過第一個元素，用 .skip(1) 就好，不必先 collect() 成 Vec 再用索引： 

fn main() {
    for arg in std::env::args().skip(1) {
        println!("{}", arg);
    }
}

.skip(n) 跟 .filter() 一樣是惰性的：它只是疊上「前 n 個不要給我」這條規則。

3. match arg.as_str()：把參數變成決定

拿到每個參數後，要判斷它是什麼。match 是這件事的自然工具，但直接寫會編譯失敗： 

let arg = String::from("--count-only");

match arg {
    "--count-only" => println!("命中"),
    _ => println!("其他"),
}

編譯器說：expected `String`, found `&str`。

原因是 env::args() 給的每個參數都是 String（有所有權的字串），而 "--count-only" 這種字面值是 &str（借來的字串切片）。 match 要求被比對的值和每個 pattern 是同一個型別。

.as_str() 就是那個轉接頭：它從 String 借出一個 &str，不複製內容。 

match arg.as_str() {
    "--count-only" => println!("命中"),
    _ => println!("其他"),
}

4. 守衛（guard）：pattern 之外的額外條件

還有一種參數要處理：--verbose 這種我們沒實作的選項。它不等於任何已知的字面值，但它開頭是 -，所以它顯然是想當一個選項，不是檔名。

match 的每個分支可以在 pattern 後面加一個 if 條件，這叫守衛（guard）。這一個分支要成立，pattern 要對，守衛也要為 true： 

fn main() {
    for arg in std::env::args().skip(1) {
        match arg.as_str() {
            "--count-only" => println!("開啟只算數量模式"),
            _ if arg.starts_with('-') => println!("不認識的選項：{}", arg),
            _ => println!("檔名：{}", arg),
        }
    }
}

用 --count-only --verbose notes.txt 跑這支程式，會依序印出三行：開啟只算數量模式、不認識的選項：--verbose、檔名：notes.txt。

  • _ if arg.starts_with('-')：_ 接受任何值， 守衛再把範圍縮小到「開頭是 -」。守衛裡可以用當前作用域的任何變數，不限於被比對的那個值。
  • 順序有意義：match 從上往下找第一個成立的分支。 "--count-only" 必須寫在守衛之前，否則它會先被守衛那一行接走。
  • 最後的 _：剩下的都當檔名。
💡 對照 TypeScript：TS 的 switch 沒有守衛，遇到這種需求只能寫成 default: 裡再 if。Rust 的守衛讓「條件」和「分支」留在同一層，不必多包一層縮排。

5. 不認識的選項是錯誤，不是提示

使用者打錯選項名稱時，程式應該失敗，而不是印一行訊息然後照常執行。 否則使用者會以為選項生效了。

你已經有處理錯誤的機制了：AppError。加一個帶資料的變體，把打錯的那個選項存進去： 

// errors.rs
pub enum AppError {
    ReadFailed(std::io::Error),
    Empty,
    UnknownFlag(String),
}
// 在 Display 的 match 裡多一個分支
AppError::UnknownFlag(flag) => write!(f, "不認識的選項：{}", flag),

然後在守衛那一行 return Err(AppError::UnknownFlag(arg))。

剩下的事情不用改。run() 回傳 Err，main() 印到 stderr 並 exit(1) —— 這是第 18 課就架好的。新的錯誤自動走同一條路。

小測驗一：match arg { "--help" => ..., _ => ... }（arg 是 String）為什麼編譯不過？
小測驗二：把 _ if arg.starts_with('-') 這個分支移到 "--count-only" 上面，會發生什麼？

換你動手

幫 hello_cli 加上 --count-only：
  1. 在 errors.rs 的 AppError 加一個變體 UnknownFlag(String)，並在 Display 的 match 裡補上對應分支。
  2. 在 run() 裡宣告兩個變數：let mut filename: Option<String> = None; 和 let mut count_only = false;。
  3. 用 for arg in env::args().skip(1) 走過每個參數， 用 match arg.as_str() 加守衛分成三種情況： --count-only 把旗標設成 true、開頭是 - 的回傳 Err、其餘的存進 filename。
  4. 原本的 args.get(1) 那段 match 換成對 filename 這個 Option 做 match； None 的分支把用法訊息更新成 用法：cargo run -- [--count-only] <檔名>。
  5. 把 println!("{}", report.content); 包進 if !count_only { ... }。

驗證條件：cargo test 四個測試仍然全過（這一課只動 main.rs 和 errors.rs，report.rs 的行為不該改變），然後手動跑這五種情況：

指令 預期
cargo run -- notes.txt 跟以前一樣，內容和統計都印出來
cargo run -- --count-only notes.txt 只有標題行和統計，檔案內容不印
cargo run -- notes.txt --count-only 跟上一列完全一樣（順序不影響結果）
cargo run -- --verbose notes.txt 不認識的選項：--verbose，離開碼 1
cargo run -- nope.txt 讀不到檔案：...，離開碼 1（沒有壞掉）
💡 如果 load_report 抱怨型別：它收 &str，而你現在手上是 String。寫 load_report(&filename) 就好，&String 會自動轉成 &str。編譯器訊息貼給我也可以，我幫你看。
這一課的成果
hello_cli 現在會解析選項了，而且不靠參數位置。這是它第一次像一個真正的 CLI 工具而不是練習程式：選項順序隨便放，打錯選項會明確失敗並回報離開碼 1。
