HashMap：統計每個詞出現幾次

學習目標：學會用 HashMap 存「鍵 → 值」的對應，用 entry().or_insert() 做計數，並知道 HashMap 沒有順序這件事會怎麼影響你的輸出。

1. 為什麼 count_kinds 的做法不夠用

count_kinds 回傳 (usize, usize, usize)，三個數字對應三種類型的行。這行得通，因為你事先就知道有哪三種。

現在換一個問題：統計檔案裡每個詞出現幾次。你事先不知道會有哪些詞，也不知道總共有幾種詞。

這種「鍵事先不知道、要邊跑邊長出來」的統計，需要的是 HashMap。

2. HashMap 的基本操作

HashMap<K, V> 用來儲存「鍵 → 值」的對應。K 是鍵的型別，V 是值的型別。

它不在預設引入的範圍內，要自己 use： 

use std::collections::HashMap;

fn main() {
    let mut counts: HashMap<String, usize> = HashMap::new();

    counts.insert(String::from("apple"), 3);
    counts.insert(String::from("banana"), 2);

    println!("{:?}", counts.get("apple"));  // Some(3)
    println!("{:?}", counts.get("durian")); // None
    println!("{}", counts.len());           // 2
}
  • .insert(鍵, 值)：寫入。鍵已經存在的話，舊值被蓋掉。
  • .get(&鍵)：讀取，回傳 Option。 有就是 Some(值)，沒有就是 None。
  • .len()：目前有幾組對應。

注意 .get() 回傳的是 Option，不是值本身。這是必然的 —— 鍵可能不存在，而「不存在」需要一個表達方式。這跟你上一課用 Option<String> 來存檔名是同一個道理。

還有一個細節：.get() 給的是參考，型別是 Option<&V>，因為值的所有權還留在 HashMap 裡面。印出來看不出差別（Some(3)），但要拿它跟其他數值比對時就得寫成 Some(&3)。等一下寫測試會用到。

💡 對照 TypeScript：最接近的是 Map<K, V>， set / get / size 一一對應。差別在讀取：TS 的 map.get(k) 回傳 V | undefined，你可以直接拿來用；Rust 給你 Option<&V>，你必須先處理 None 的情況，才能安全地取出值。

3. entry().or_insert()：計數的標準寫法

計數會遇到一個尷尬的情況：第一次看到某個詞時，它還不在 HashMap 裡，不能直接加一。用 get 寫出來會變成這樣： 

// 這段可以動，但沒有人這樣寫
match counts.get(word) {
    Some(n) => counts.insert(word.to_string(), n + 1),
    None => counts.insert(word.to_string(), 1),
};

標準寫法是 entry： 

*counts.entry(word.to_string()).or_insert(0) += 1;

這一行拆開來看：

  • .entry(鍵)：拿到「這個位置」的把手，不管它現在有沒有值。
  • .or_insert(0)：如果位置是空的，就先塞 0 進去。 然後不論是原本就有的值還是剛塞的 0，都回傳一個指向它的可變參考（&mut usize）。
  • 開頭的 *：解開（dereference）那個可變參考，才能對它裡面的數字做 += 1。少了 *，你是在對參考本身做加法，編譯不過。

所以整句話是：「找到這個詞的位置，沒有的話就從 0 開始，然後把它加一。」

完整的統計函式：

use std::collections::HashMap;

fn word_counts(content: &str) -> HashMap<String, usize> {
    let mut counts = HashMap::new();

    for word in content.split_whitespace() {
        *counts.entry(word.to_string()).or_insert(0) += 1;
    }

    counts
}

fn main() {
    let counts = word_counts("apple banana apple");

    println!("{:?}", counts.get("apple"));  // Some(2)
    println!("{}", counts.len());           // 2
}
  • .split_whitespace()：把字串依照空白分隔，切成一個個詞的疊代器。跟 lines() 一樣是字串的疊代器來源之一（見疊代器速查表）。
  • word.to_string()：split_whitespace() 給的是借來的 &str，但 HashMap 需要擁有鍵的所有權，所以複製一份成 String。
  • HashMap::new() 沒寫型別標註。編譯器會從後面的用法自動推斷出它是 HashMap<String, usize>。

4. HashMap 沒有順序

直接走訪一個 HashMap，出來的順序是不固定的。不是插入順序，也不是排序後的順序。同一支程式跑三次，可以得到三種順序： 

["date", "cherry", "apple", "banana", "elderberry"]
["date", "elderberry", "apple", "banana", "cherry"]
["elderberry", "apple", "date", "banana", "cherry"]

這不是 bug。HashMap 的工作是「快速用鍵找值」，順序不在它的職責裡。

所以如果輸出的結果是要給人看的，就得自己決定順序：先 collect() 成 Vec，再排序。 

let mut pairs: Vec<(&String, &usize)> = counts.iter().collect();
pairs.sort();

for (word, count) in pairs {
    println!("{} {}", word, count);
}
  • .iter()：走訪 HashMap，每次產生一組 (&鍵, &值) 的 tuple。
  • .sort()：tuple 的排序是先比第一個元素，所以這裡等於按照詞的字母順序排。
小測驗一：*counts.entry(k).or_insert(0) += 1; 開頭那個 * 是在做什麼？
小測驗二：直接用 for (k, v) in &counts 印出整個 HashMap，順序會是什麼？

換你動手

幫 hello_cli 加上 --words：
  1. 在 hello_cli/ 底下新增一個測試檔 words.txt，內容兩行： apple banana apple 和 cherry banana apple。
  2. 在 report.rs 最上面加 use std::collections::HashMap;， 並在 impl Report 裡加一個方法 pub fn word_counts(&self) -> HashMap<String, usize>， 用 split_whitespace() 加 entry().or_insert(0) 實作。
  3. 在 mod tests 裡加第五個測試：用 Report::new("test.txt", "code code // comment".to_string())， 確認 counts.get("code") 是 Some(&2)、 counts.get("nothing") 是 None、counts.len() 是 3。（get 回傳的是參考，所以是 Some(&2) 不是 Some(2)。）
  4. 在 main.rs 加一個 --words 旗標（跟上一課的 --count-only 同一個 match 裡多一行）。
  5. 旗標開啟時，把 word_counts() 的結果 collect 成 Vec、sort()、逐行印出，然後 return Ok(());。--words 是獨立模式，印完就結束。
💡 位置很重要：這段要放在 report.add_title() 之前。add_title 會把 === 檔名 === 插進 content，在它之後統計的話，標題裡的字會被算成詞。

驗證條件：cargo test 五個測試全過，然後：

指令 預期
cargo run -- --words words.txt apple 3 / banana 2 / cherry 1，就是這個順序
同一個指令再跑幾次 順序每次都一樣（因為你排序了）
cargo run -- notes.txt 跟以前一模一樣，沒被影響
cargo run -- --count-only notes.txt 也跟以前一樣
這一課的成果
你手上多了 Rust 最常用的第二種集合。Vec 管「一串東西」，HashMap 管「用鍵查值」，日常寫程式幾乎都在這兩個之間打轉。

而且 hello_cli 現在會做一件它本來做不到的事：統計事先不知道有哪些種類的項目。
