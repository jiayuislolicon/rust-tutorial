Lesson 0014 · Rust · CLI 工具養成路線

enum 與資料建模

目標：能定義一個 enum 表達「只能是這幾種之一」的資料，能用 match 分辨每個變體，並幫 hello_cli 的 Report 加上「把每一行分類」的能力。

你其實從第一堂課就在用 enum 了，只是沒看過 enum 這個關鍵字：Option 和 Result 都是 enum。Option 有兩個變體 Some(T)、None；Result 有兩個變體 Ok(T)、Err(E)。這一課要教的，是怎麼自己定義一個這樣的型別。

struct 是「且」，enum 是「或」

Lesson 13 的 struct Report 把 filename、content、line_count 綁在一起 —— 一個 Report 同時擁有這三個欄位，是「且」的關係。enum 相反：一個值只會是列出的變體之一，是「或」的關係。 

enum LineKind {
    Empty,
    Comment,
    Code,
}

一個 LineKind 只會是 Empty、Comment、Code 三者之一，不會同時是兩個。建立一個值要寫 LineKind::Empty（用 ::，跟關聯函式一樣的語法，因為變體本質上就是「型別底下的一個東西」）。

用 match 分辨變體

拿到一個 LineKind 之後，用 match 分辨它是哪個變體 —— 跟你在 Lesson 8、9 拆 Option、Result 時做的事完全一樣： 

fn describe(kind: LineKind) -> &'static str {
    match kind {
        LineKind::Empty => "空行",
        LineKind::Comment => "註解",
        LineKind::Code => "程式碼",
    }
}
match 一定要列完所有變體。少寫一個變體，編譯器直接報錯，不會等到執行期才出包。這跟 match 拆 Option 時你必須寫 None 那個分支，是同一條規則 —— GLOSSARY.md 裡 match 那條寫的「exhaustive」。

變體也能帶資料

目前 LineKind 的三個變體都是空的，只是三個名字。但變體其實可以像 struct 一樣帶著資料 —— 你早就見過這種用法，只是沒注意：Option 的兩個變體裡，Some 帶著資料，None 不帶；Result 的兩個變體裡，Ok 和 Err 都帶著資料（分別是成功的值、失敗的原因）。 

Some(name)   // Option 的 Some 變體，帶著一個 T
Ok(content)  // Result 的 Ok 變體，帶著一個 T
Err(error)   // Result 的 Err 變體，帶著一個 E

match 拆變體的同時，也把它帶的資料取出來綁到一個名字上（name、content、error）—— 這就是你在 match fs::read_to_string(filename) { Ok(content) => ..., Err(error) => ... } 裡一直在做的事。自己定義的 enum 也能這樣寫： 

enum LineKind {
    Empty,
    Comment,
    Code(String),   // 帶著這一行程式碼本身
}

match kind {
    LineKind::Empty => println!("空行"),
    LineKind::Comment => println!("註解"),
    LineKind::Code(text) => println!("程式碼：{}", text),
}

換你動手

幫 hello_cli 的 Report 加一個「把每一行分類」的能力：數出檔案裡有幾行是空行、幾行是註解（用 // 開頭判斷）、幾行是程式碼。這個方法要一次回傳三個數字，用得到 tuple（元組）——一個固定大小、可以裝好幾個值的容器，寫成 (a, b, c)，取值用 .0、.1、.2（第幾個位置，從 0 開始）： 

fn pair() -> (usize, usize) {
    (1, 2)
}

let (a, b) = pair();   // 呼叫端可以直接拆開接住
println!("{} {}", a, b);
四個步驟：
  • 在 main.rs 最上面定義 enum LineKind { Empty, Comment, Code }（先不用帶資料的版本）。
  • 在 impl Report 裡加一個關聯函式 fn classify_line(line: &str) -> LineKind：用 if/else 判斷 line.trim().is_empty()、line.trim().starts_with("//")，回傳對應的 LineKind 變體。
  • 在 impl Report 裡加一個方法 fn count_kinds(&self) -> (usize, usize, usize)：用 for line in self.content.lines() 搭配 match Report::classify_line(line) { ... }，把三種變體各自的次數累加起來，最後回傳一個 tuple (empty, comment, code)。
  • 在 main 裡呼叫 report.count_kinds()，把三個數字印出來。

成功條件：cargo run -- notes.txt 除了原本的標題和內容，還會印出空行、註解、程式碼各幾行，三個數字加起來要等於總行數。

這一課的成果
你現在能用 enum 表達「只能是這幾種之一」的資料，並用 match 安全地分辨每一種、不怕漏掉任何一種。這直接對應 MISSION.md「設計 struct 和 enum 來塑模 CLI 工具資料」這條成功標準的後半段 —— Option、Result 從今天起不再是「兩個特別的東西」，而是「跟你自己寫的 LineKind 同一種東西」。速查表：enum 與 match 參考卡。
