Serde — 結構化序列化

學習目標： 你的 JsonFormatter 用 format! 手拼 JSON 字串——一般檔名下能動，但檔名裡只要多一個雙引號就會產出非法 JSON。這一課你會換成 Rust 生態系的標準做法：用 serde 描述「要輸出哪些欄位」，再交給 serde_json 產生合法、可解析的 JSON。

1. 手拼字串會在哪裡翻車

先來看現在的寫法。打開 formatter.rs 裡的 JsonFormatter： 

format!(
    "{{
  \"filename\": \"{}\",
  \"lines\": {},
  \"empty\": {},
  \"comment\": {},
  \"code\": {}
}}",
    report.filename,
    report.line_count(),
    stats.empty,
    stats.comment,
    stats.code,
)

對大多數正常檔名，這段程式碼看起來沒問題。但試想檔名裡剛好有一個雙引號——例如 say"hi".rs——拼出來的字串會長這樣： 

{
  "filename": "say"hi".rs",
  ...
}

這不是合法的 JSON。下游若用 JSON.parse 或任何正式 parser 讀它，都會直接失敗。而且這只是其中一種翻車方式：逗號漏寫、括號少一個、欄位值含換行——手拼字串時，同一類問題會一再出現。

你真正需要的不是「長得很像 JSON 的字串」，而是「從一個 Rust 值，可靠地變成某種文字格式」。這件事有專門的名字：序列化（serialization）。

2. 序列化：TypeScript 裡你已經做過

在 TypeScript 裡，你幾乎不會手拼 JSON：

JSON.stringify({
  filename: report.filename,
  lines: report.lineCount(),
  empty: stats.empty,
  comment: stats.comment,
  code: stats.code,
});

你把一個物件交出去；跳脫字元、逗號、括號怎麼放，全由函式庫處理。

Rust 裡對應的標準答案是 Serde——一個專門做序列化與反序列化的框架。Serde 本身不綁定某一種格式；JSON、TOML、YAML 各自有一個負責該格式的 crate。這一課用的是處理 JSON 的 crate：serde_json。

角色 crate 做什麼
框架 serde 定義 Serialize／Deserialize trait；提供 #[derive(Serialize)]
JSON 格式 serde_json 把實作了 Serialize 的值變成 JSON 字串（或反過來）
💡 Serialize 與 Deserialize。Serialize 是「Rust 值 → 文字」；Deserialize 是「文字 → Rust 值」。這一課只需要 Serialize——你的工具是在 輸出 JSON。讀設定檔、解析 API 回應時才會用到 Deserialize；概念相同，只是方向相反。

3. 加入兩個依賴

在 hello_cli/ 目錄執行：

cargo add serde --features derive
cargo add serde_json

和上一課的 clap 一樣，derive feature 開啟之後才能寫 #[derive(Serialize)]。serde_json 不需要額外 feature。

完成後 Cargo.toml 會多兩行：

[dependencies]
clap = { version = "4", features = ["derive"] }
serde = { version = "1", features = ["derive"] }
serde_json = "1"

4. 專用的 view struct，不要直接 Serialize Report

直覺上，你可能想在 Report 上加 #[derive(Serialize)]。但 Report 裡有 content——整份檔案內容——直接序列化會把全文也塞進 JSON。你現在的輸出只要摘要欄位，不需要那些。

正確做法是另建一個 struct，只裝「要輸出的欄位」。這種 struct 有時叫 view struct——它描述的是輸出長什麼樣，而不是內部資料模型長什麼樣。在 formatter.rs 頂部加上 import，並定義： 

use serde::Serialize;

#[derive(Serialize)]
struct ReportJson<'a> {
    filename: &'a str,
    lines: usize,
    empty: usize,
    comment: usize,
    code: usize,
}

struct 定義完之後，有三個細節值得對一下：

  • #[derive(Serialize)] 和 #[derive(Debug)]、#[derive(Parser)] 一樣——編譯器看著欄位，自動產生 impl Serialize。
  • 欄位名就是 JSON 的 key。想改名字可以用 #[serde(rename = "...")]；這一課用不到。
  • filename: &'a str 借用現有的 report.filename，不必再 .clone()。lifetime 'a 你在 Lesson 34 見過——這裡的意思很單純：這個 struct 不能活得比它借用的字串還久。

然後改寫 JsonFormatter：

impl Formatter for JsonFormatter {
    fn format_report(&self, report: &Report) -> String {
        let stats = report.line_stats();
        let json = ReportJson {
            filename: &report.filename,
            lines: report.line_count(),
            empty: stats.empty,
            comment: stats.comment,
            code: stats.code,
        };
        serde_json::to_string_pretty(&json)
            .expect("ReportJson should always serialize")
    }
}

to_string_pretty 回傳的是 Result<String, _>，不是直接的 String。對只含 &str 和數字的 ReportJson 來說，序列化實際上不會失敗；這裡用 expect 是在說「若真的失敗，代表程式邏輯有 bug」。函式名裡的 _pretty 表示縮排漂亮的輸出；若不要換行，用 to_string 就好。

5. 比較前後，並讓測試真的解析 JSON

前面說過，手拼字串只能保證「看起來像」JSON。換成 Serde 之後，你可以直接比較前後差異：

🔴 手拼字串——看起來像 JSON
format!(
    "{{\n  \"filename\": \"{}\",\n  \"lines\": {},\n  ...
}}",
    report.filename,
    report.line_count(),
    ...
)
🟢 Serde——從 struct 產生合法 JSON
#[derive(Serialize)]
struct ReportJson<'a> { filename: &'a str, lines: usize, ... }

serde_json::to_string_pretty(&json).expect("...")

換完之後，測試也能跟著升級。以前你只能寫 output.contains("\"lines\": 3")，猜字串「看起來像不像」對的 JSON；現在可以直接 parse，確認它真的是合法 JSON： 

#[test]
fn json_formatter_produces_valid_structure() {
    let report = Report::new("test.rs", "let x = 1;\n// hi\n\n".to_string());
    let output = JsonFormatter.format_report(&report);
    let value: serde_json::Value =
        serde_json::from_str(&output).expect("output should be valid JSON");
    assert_eq!(value["filename"], "test.rs");
    assert_eq!(value["lines"], 3);
    assert_eq!(value["empty"], 1);
    assert_eq!(value["comment"], 1);
    assert_eq!(value["code"], 1);
}

serde_json::Value 代表「任意 JSON 值」——類似 TypeScript 裡 JSON.parse 之後、還沒對到具體 interface 的結果。用 value["key"] 取值，測試就能確認：輸出不只是長得像 JSON，而是真的可以被 parse。

6. 動手做

  1. 執行 cargo add serde --features derive 與 cargo add serde_json。
  2. 在 formatter.rs 定義 ReportJson，加上 #[derive(Serialize)]。
  3. 把 JsonFormatter::format_report 改成組裝 ReportJson，再呼叫 serde_json::to_string_pretty。
  4. 把 JSON 測試改成用 serde_json::from_str 解析後再 assert_eq!。
  5. 跑 cargo test，再跑 cargo run -- --format json src/main.rs 看輸出。
💡 PlainFormatter、make_formatter 和 main.rs 都不需要改。trait object 那一層仍然成立——你換的只是 JSON 那條實作路徑內部怎麼產生字串。

這一課的成果
你不再手拼 JSON 字串，而是先描述結構、再交給函式庫輸出。

三件帶走的事：
  • Serialize——用 derive 宣告「這個 struct 可以變成某種格式」
  • serde_json::to_string_pretty——把值變成合法、可讀的 JSON
  • view struct——輸出形狀和內部資料模型可以分開，不必把整份 Report 都倒出去
