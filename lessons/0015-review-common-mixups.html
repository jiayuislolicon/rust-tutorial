複習：釐清容易混淆的概念

目標：把 Lesson 11～14 裡幾組容易混在一起的概念，重新拆開、各自釐清。這堂課沒有新知識，也沒有動手練習。

這幾課教得很密集，幾個概念名字或語法有點像，容易黏在一起。這堂課把它們一組一組拆開，每組先自己回想一次再看答案。

第一組：可變性 vs 生命週期

這兩個是完全不同的軸，只是常常一起出現在同一個錯誤訊息附近。

 問的問題錯誤代號解法
可變性（mutability）這個值能不能被改？E0596宣告時加 let mut
生命週期（lifetime）這個引用能活多久？E0106之後的課才教

report.add_title() 報錯 cannot borrow as mutable，是因為 report 宣告時沒寫 mut —— 跟這個引用能活多久完全無關。'static 講的是「活到程式結束」，是生命週期，不是可變性。

小測驗：let report = Report::new(...); report.add_title(); 報錯 cannot borrow as mutable，該加的是什麼？

第二組：struct vs enum

一個字記住：struct 是「且」，enum 是「或」。 

struct Report { filename: String, content: String }  // 同時擁有兩個欄位（且）
enum LineKind { Empty, Comment, Code(String) }        // 只會是其中一個變體（或）
小測驗：想表達「這個值只會是三種狀態之一，不會同時是兩種」，該用哪個？

第三組：method vs 關聯函式

差別只看一件事：第一個參數有沒有 self。 

fn summary(&self) -> String { ... }         // 有 self → 方法，用 report.summary() 呼叫
fn new(filename: &str) -> Report { ... }    // 沒 self → 關聯函式，用 Report::new(...) 呼叫
小測驗：String::from("hi") 這個呼叫方式（用 ::），代表 from 是哪一種？

第四組：tuple vs struct

兩個都能把幾個值裝在一起，差別是有沒有名字。 

(usize, usize, usize)                          // tuple：靠位置，取值用 .0 .1 .2
struct Counts { empty: usize, comment: usize, code: usize }  // struct：靠名字，取值用 .empty

只是暫時要回傳兩三個值、彼此意義從上下文就看得出來，用 tuple 快速方便。如果這幾個值會被到處傳遞、名字容易搞混，換成 struct 更清楚——這也是為什麼 Lesson 13 把 filename/content/line_count 收成 Report，而不是繼續用三個獨立變數或一個 tuple。

小測驗：tuple 的 .0、.1 是靠什麼取值的？（兩個字，中文）

impl 怎麼跟 struct 對上的

最後複習一次容易誤解的一點：impl Report 跟 struct Report 是靠名字一樣對上的，跟兩段程式碼寫在檔案裡的哪個位置完全無關。一個 struct 也可以拆成好幾個 impl 區塊，不用全部擠在一起。

這一課的目的
沒有新技能要學，純粹把 Lesson 11～14 裡容易黏在一起的幾組概念重新拆乾淨：可變性 ≠ 生命週期、struct（且）≠ enum（或）、方法（.）≠ 關聯函式（::）、tuple（位置）≠ struct（名字）。下一課會開始教錯誤處理，這幾組概念都會繼續用到。
