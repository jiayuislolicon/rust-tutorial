Option 與缺席的值

目標：能用 Option 處理「這個值可能根本不存在」的情況，讓程式在使用者忘記給參數時給出友善說明，而不是當場崩潰。

上一課的工具有一個洞。它能讀檔、檔案不存在也不會崩潰 —— 但如果使用者完全沒給參數就直接執行： 

$ cargo run
thread 'main' panicked at src/main.rs:6:25:
index out of bounds: the len is 1 but the index is 1

崩潰了。原因很直白：沒給參數時 args 裡只有一個東西（程式自己的路徑），長度是 1，合法索引只有 args[0]。你卻要求 args[1]，這個位置不存在，Rust 只能讓程式當掉。

為什麼這是真的 bug：使用者忘記打檔名是完全正常的操作 —— 這是可以預期的使用者錯誤，跟 Lesson 8 裡「檔案不存在」是同一類。可預期的錯誤要好好回應，不該讓程式崩潰。這也是 MISSION.md 明確列出的目標之一。

Rust 沒有 null

很多語言用 null / nil / None 表示「沒有值」，而問題在於：任何值都可能偷偷是 null，你永遠不知道哪一行會炸。Rust 選了另一條路 —— 它根本沒有 null。取而代之的是一個叫 Option 的 enum： 

enum Option<T> {
    None,       // 沒有值
    Some(T),    // 有值，值就裝在裡面
}

關鍵差別是：「可能沒有值」這件事被寫進型別裡了。一個 String 保證那裡有一個字串 —— 它可以是空字串，但一定存在；只有 Option<String> 才可能連字串都沒有。

let a: String         = String::new();       // 空字串
let b: Option<String> = None;                // 沒有字串
let c: Option<String> = Some(String::new()); // 有一個空字串

b 和 c 是不同的狀態，這個差別在真實 CLI 裡有意義：使用者打 --name ""（給了名字，只是名字是空的）跟完全沒打 --name（沒給名字），你可能想有不同反應。

而「寫進型別裡」實際的感覺就是編譯器會擋你。對 Option<String> 直接呼叫字串的方法會編不過：

error[E0599]: no method named `to_uppercase` found for enum `Option<T>`
note: the method `to_uppercase` exists on the type `String`

編譯器的意思是：你手上這個東西還不確定有沒有 String，所以不能當成 String 來用。

要用到裡面的 String，得先把 Option 拆開。怎麼拆就是下一節的事。

對比一下有 null 的語言：同樣這一行會編譯成功，然後在執行時炸掉。Rust 把炸點從執行時搬到了編譯時。

你已經會這個形狀了。Lesson 6 的 Result 是 Ok(T) / Err(E)，Option 是 Some(T) / None —— 兩個變體、用 match 拆開、編譯器強制窮盡。差別只在語意：Result 說的是「成功還是失敗」，Option 說的是「有還是沒有」。少了值不一定是錯誤。

.get() 取代中括號

索引語法 args[1] 的態度是「這裡一定有東西，沒有就當掉」。Vec 另外提供了一個誠實版本： 

let args: Vec<String> = env::args().collect();

args[1]         // &String —— 越界就 panic
args.get(1)     // Option<&String> —— 越界回傳 None

.get(1) 不會崩潰。它回傳 Option<&String>：有第 1 個元素就是 Some(&"notes.txt")，沒有就是 None。危險從「執行時當掉」搬到了「型別裡的一個分支」，而分支是你能處理的東西。

用 match 收掉

use std::env;
use std::fs;

fn main() {
    let args: Vec<String> = env::args().collect();

    let filename = match args.get(1) {
        Some(name) => name,
        None => {
            println!("用法：cargo run -- <檔名>");
            return;
        }
    };

    match fs::read_to_string(filename) {
        Ok(content) => println!("{}", content),
        Err(error) => println!("讀不到檔案 {}：{}", filename, error),
    }
}
兩個新東西：
  • match 當成值用。let filename = match ... ; —— 整個 match 求值成一個東西再綁給 filename。這就是 Lesson 3 的「區塊即表達式」，只是換到 match 上。Some(name) => name 這條分支的值就是 name。
  • return 提早離開。None 分支沒有檔名可以給出去，所以印完用法就 return 結束 main。這讓兩條分支的型別不衝突：一條給出 &String，另一條根本不會回來。
如果「沒有值」時你想用預設值而不是結束程式，Option 上有現成的捷徑：args.get(1).unwrap_or(&default) —— 是 Some 就用裡面的值，是 None 就用你給的那個。Option 有幾十個這種方法（std 文件），但先把 match 練熟：看得懂 match，那些捷徑之後都只是省字。

換你動手

把 hello_cli/src/main.rs 改成沒給參數也不會崩潰。先不要往上翻，憑記憶寫 —— 想不起來再回頭看。成功條件是這三個指令： 

cargo run -- notes.txt   # 印出檔案內容
cargo run -- nope.txt    # 印出讀不到檔案的訊息
cargo run                # 印出用法說明，且不出現 panicked at

這一課的成果
你的工具現在對三種輸入都有正確反應：正常檔名、不存在的檔名、完全沒給參數 —— 而且沒有任何一條路徑會 panic。這就是 MISSION.md 裡「不 panic 地處理錯誤」那條目標。你也拿到了 Rust 兩大核心 enum 的第二個：Result 管失敗，Option 管缺席，之後幾乎每個 Rust API 都建立在這兩個之上。

主要參考資料：The Rust Programming Language — 6.1 Defining an Enum，其中「The Option Enum and Its Advantages Over Null Values」一節就是這課的正宗來源（繁中版：rust-lang.tw）。API 細節見 std::option::Option 與 slice::get。速查表：Option 與 Result 參考卡。
