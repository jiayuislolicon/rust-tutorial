Lesson 0005 · Rust · CLI 工具養成路線

讀取使用者輸入

目標：能從終端機讀進一行使用者輸入的文字，並轉成需要的型別來用。

前四課處理的都是程式內部寫死的資料。這一課讓程式第一次真的跟外界互動 —— 讀使用者從鍵盤打的東西。這是任何互動式 CLI 工具的起點，也會把前幾課的 mut、shadowing、函式回傳值全部用上一次。

讀一行輸入

use std::io;

fn main() {
    println!("你叫什麼名字？");

    let mut input = String::new();
    io::stdin()
        .read_line(&mut input)
        .expect("讀取輸入失敗");

    let name = input.trim();
    println!("哈囉，{}！", name);
}
逐行拆解：
  • use std::io; 把標準函式庫的 io 模組引入，之後才能寫 io::stdin()。
  • let mut input = String::new(); 先建一個空字串，一定要 mut —— 待會 read_line 要把讀到的文字寫進這個變數。
  • io::stdin().read_line(&mut input) 讀一行輸入，附加到 input 後面（不是回傳新字串，是直接改 input 本身，所以要傳 &mut —— 可變借用）。
  • input.trim() 去掉結尾的換行符號 —— 使用者按 Enter 送出時，那個換行也會被讀進 input 裡，不去掉的話後面比對字串會出問題。這裡用了 shadowing：name 是從 input 轉換出來的新綁定。

.expect(...) 是什麼？

read_line 有可能失敗（例如輸入來源出問題），所以它回傳一個 Result，代表「成功或失敗」兩種可能。.expect("訊息") 的意思是：如果失敗，直接讓程式當掉，並印出這個訊息。

這不是正式的錯誤處理方式，只是「先讓它動起來」的捷徑 —— Result、match、真正妥善的錯誤處理是後面專門一課的主題。現在只要記得：看到 .expect(...)，代表這裡假設「正常來說不會失敗」。

把輸入轉成數字

讀進來的永遠是文字（String），想當數字用要自己轉換 —— 這正好用上 Lesson 2 教過的 shadowing 轉換鏈：

let mut input = String::new();
io::stdin().read_line(&mut input).expect("讀取輸入失敗");

let age: i32 = input.trim().parse().expect("請輸入一個數字");
println!("明年你 {} 歲", age + 1);

.parse() 嘗試把字串轉成 age: i32 標註的型別；轉換也可能失敗（使用者打了文字而不是數字），所以一樣用 .expect(...) 先簡單處理。

小測驗：如果拿掉 input.trim() 直接寫 input.parse()，使用者輸入 25 後按 Enter，結果會怎樣？（用 3 個字回答，例如「會失敗」或「正常執行」這種長度）
這一課的成果
你現在能讀一行使用者輸入、用 trim() 清掉換行、並用 parse() 轉成需要的型別。前五課的東西加起來，你已經能寫一個會跟使用者互動的最小 CLI 工具了。下一課會把這些串起來，寫一個完整的小工具，並開始碰到需要「正式處理錯誤」的地方。
