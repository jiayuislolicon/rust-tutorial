struct 與自訂型別

目標：能定義一個 struct 把相關資料包成一個型別，能寫 impl 幫它加方法，並且能把 hello_cli 現在四散的變數收成一個型別。

先看你目前的 hello_cli/src/main.rs 大概長什麼樣子（把 Lesson 9、11、12 教過的東西接起來）： 

use std::env;
use std::fs;

fn add_title(content: &mut String, filename: &str) {
    content.insert_str(0, &format!("=== {} ===\n", filename));
}

fn line_count(text: &str) -> usize {
    text.lines().count()
}

fn main() {
    let args: Vec<String> = env::args().collect();

    let filename = match args.get(1) {
        Some(name) => name,
        None => {
            println!("用法：cargo run -- <檔名>");
            return;
        }
    };

    match fs::read_to_string(filename) {
        Ok(mut content) => {
            println!("共 {} 行", line_count(&content));
            add_title(&mut content, filename);
            println!("{}", content);
        }
        Err(error) => println!("讀不到檔案 {}：{}", filename, error),
    }
}

如果你的檔案跟這段不完全一樣，先把它換成這樣，這一課從這裡繼續蓋。

filename、content、line_count(&content) 這三個東西其實是同一份資料的三個面向 —— 都在講「這個檔案」。但它們是三個獨立的變數，函式簽名也一個個分別傳。資料多起來之後（檔案大小、修改時間、行數上限……），這種傳法會越來越亂。

struct：把相關資料包成一個型別

struct Report {
    filename: String,
    content: String,
    line_count: usize,
}

struct 定義一個新型別，裡面每一項叫欄位（field），每個欄位都要標型別 —— 跟宣告變數一樣。這個定義本身不產生任何資料，它只是一張「這個型別長什麼樣」的藍圖。

建立一個實例

let report = Report {
    filename: filename.to_string(),
    content: content,
    line_count: 3,
};

println!("{}", report.filename);      // 用 . 取欄位
println!("{}", report.content);
println!("{}", report.line_count);

每個欄位都要給值，順序不限，但名字要對上。用 . 加欄位名稱就能取值，跟你一路用到現在的 args[0]、content.len() 是同一個 . 語法。

欄位為什麼是 String 不是 &str？Lesson 12 已經回答過這題：&str 欄位要標 lifetime（error[E0106]: missing lifetime specifier），那是另一課的東西。String 讓 Report 自己擁有這份資料，不需要管「借的那份資料會不會先死掉」。這也是為什麼上面 filename.to_string() 要轉一次 —— filename 是 &String，欄位要的是 String。

簡寫：欄位名跟變數名一樣時

上面 content: content 這種「欄位名 = 變數名」的情況很常見，Rust 讓你省掉重複： 

let content = String::from("...");
let line_count = 3;

let report = Report {
    filename: filename.to_string(),
    content,        // 等於 content: content
    line_count,     // 等於 line_count: line_count
};

只有名字完全一樣才能省。filename: filename.to_string() 因為右邊多了一個 .to_string()，不是單純的變數名，所以還是要寫全。

impl：幫型別加方法

現在 line_count 是一個獨立函式，呼叫時要記得傳 &content。如果這個計算「屬於」Report，可以把它寫成方法： 

impl Report {
    fn summary(&self) -> String {
        format!("{}：共 {} 行", self.filename, self.line_count)
    }
}
println!("{}", report.summary());

impl Report { ... } 是「以下這些函式屬於 Report」的意思。裡面的函式如果第一個參數是 &self，就叫方法，呼叫時用 值.方法()，不用再手動傳那個值 —— self 指的就是 report 自己。

impl 跟 struct 是靠名字對上的，不是靠位置。編譯器看到 impl Report，就去找叫 Report 的那個 struct，兩者對上完全是因為名字一樣，跟這段程式碼寫在檔案的哪裡沒有關係。就算你把 impl Report 寫在檔案最上面、struct Report 放在最下面，也編得過。可以把它們想成兩份分開的文件：一份定義「有哪些欄位」，一份定義「有哪些方法」，靠同一個型別名接起來。一個 struct 也可以有好幾個 impl 區塊，不必全部塞在一起。
&self 就是上一課的 &。方法只是讀取欄位，寫 &self（借用）；要修改欄位，寫 &mut self（可改借用）；要把整個值吃掉不還，寫 self（移動，很少見）。跟 Lesson 11 的借用規則是同一套規則，只是套在方法上。

把 add_title 也改成方法

impl Report {
    fn summary(&self) -> String {
        format!("{}：共 {} 行", self.filename, self.line_count)
    }

    fn add_title(&mut self) {
        let title = format!("=== {} ===\n", self.filename);
        self.content.insert_str(0, &title);
    }
}
report.add_title();
println!("{}", report.content);

原本 add_title(&mut content, filename) 要傳兩個參數，因為 content 和 filename 是分開的。現在它們是同一個 report 的兩個欄位，方法只需要 &mut self 一個參數，裡面用 self.content、self.filename 就能同時碰到兩個欄位。這是 struct 的實際好處：相關資料綁在一起，函式簽名跟著變短。

關聯函式：不帶 self 的那種

你從 Lesson 1 就一直在寫 String::from(...)、Vec::new()。這兩個現在可以講清楚了 —— 它們是關聯函式（associated function）：定義在 impl 裡、但第一個參數不是 self 的函式，用型別名::函式名()呼叫，不是值.函式名()。 

impl Report {
    fn new(filename: &str, content: String) -> Report {
        let line_count = content.lines().count();
        Report {
            filename: filename.to_string(),
            content,
            line_count,
        }
    }
}
let report = Report::new(filename, content);

new 不是關鍵字，只是慣例上大家都把「造出一個實例」的關聯函式叫這個名字 —— 就像 String::from、String::new、Vec::new 一樣。方法和關聯函式的差別只有一件事：有沒有 self 當第一個參數。有，用 . 呼叫；沒有，用 :: 呼叫。

小測驗一：fn summary(&self) -> String 和 fn new(filename: &str) -> Report 這兩個函式定義在同一個 impl Report 裡，關鍵差別是什麼？
小測驗二：呼叫 report.add_title() 時，fn add_title(&mut self) 裡的 self 綁的是哪個值？
小測驗三：要幫 Report 加方法或關聯函式，要寫 ____ Report { ... } 這個區塊，關鍵字是什麼？（英文，4 個字母）

換你動手

把 hello_cli 從「三個變數 + 兩個獨立函式」改成「一個 Report struct」。

四個步驟：
  • 定義 struct Report { filename: String, content: String, line_count: usize }。
  • 寫 impl Report，裡面放 fn new(filename: &str, content: String) -> Report（在裡面算好 line_count）、fn add_title(&mut self)、fn summary(&self) -> String。
  • 改 main：Ok(content) => { ... } 分支裡呼叫 Report::new(filename, content) 造出 report（記得加 mut，add_title 要改欄位），然後依序印 report.summary()、呼叫 report.add_title()、印 report.content。
  • 刪掉原本獨立的 fn line_count 和 fn add_title —— 它們的邏輯已經搬進 impl 裡了。

成功條件：cargo run -- notes.txt 印出「檔名：共 N 行」，接著印出加了標題的完整內容，而且沒給參數、給錯檔名這兩條路徑仍然不會 panic。

這一課的成果
你現在能把散落的變數和函式收成一個有清楚邊界的型別。這是 MISSION.md「設計 struct 和 enum 來塑模 CLI 工具資料」這條目標的第一步 —— 之後你的 CLI 工具會越來越常長成「定義幾個 struct，寫幾個 impl，main 只負責串起來」的形狀。String::from、Vec::new 這些你早就在用的東西，現在也有名字了：關聯函式。速查表：struct 與 impl 參考卡。
