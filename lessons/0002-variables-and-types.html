Lesson 0002 · Rust · CLI 工具養成路線

變數與型別

目標：能宣告變數、知道何時要加 mut、認得幾個最常用的基本型別。

上一課你很快就抓到 Cargo 的專案結構，這一課節奏會快一點，直接進主題。這是後面「讀使用者輸入」「處理檔案內容」「計數/統計」的地基 —— 任何 CLI 工具都要先會存資料，才能處理資料。

預設不可變（immutable by default）

這是 Rust 和大多數語言最不一樣的地方之一。把下面貼進 hello_cli 的 src/main.rs：

fn main() {
    let attempts = 3;
    println!("attempts = {}", attempts);

    attempts = 4; // 這行會編譯錯
}

執行 cargo run，你會看到編譯器報錯：cannot assign twice to immutable variable。

為什麼要這樣設計？ 在一個沒有垃圾回收器的語言裡，「這個變數之後還會不會被改」是一個很重要的資訊 —— 編譯器可以幫你抓出「以為它不會變，結果被改掉」的 bug。想讓變數可變，要「明確申請」： 
let mut attempts = 3;
println!("attempts = {}", attempts);

attempts = 4; // 現在可以了
println!("attempts = {}", attempts);
如果你少打了最後一行 println!，編譯器會警告 unused_assignments（value assigned to attempts is never read）。這個警告跟「數字有沒有變化」無關，而是跟「這個值有沒有被讀取」有關：attempts = 4; 這個賦值之後，直到變數離開作用域為止都沒有任何地方讀取它，編譯器就會提醒你「這行賦值可能是多餘的、或你忘了寫後續程式」。這叫 dead store（死賦值）——就算存進去的值跟舊值一樣（例如又寫一次 attempts = 3;），只要沒被讀取，一樣會被警告。

幾個你會一直用到的基本型別

let count: i32 = 10;         // 整數（32 位元，帶正負號）
let ratio: f64 = 0.75;       // 浮點數
let is_valid: bool = true;   // 布林
let initial: char = 'R';     // 單一字元（注意是單引號）
let name: String = String::from("hello_cli"); // 可成長的字串

大部分時候你不用手動寫型別（像上面的 : i32）—— 編譯器會從賦予的值自動推斷。上面特地寫出來是為了讓你看清楚每個變數的型別是什麼。實務上你只會在編譯器推斷不出來、或想強調意圖時才手動標註。

先別深究 String： 你會注意到字串用了 String::from(...)，而不是像其他型別一樣直接寫字面值。這牽涉到 Rust 的所有權（ownership）機制 —— 這是之後專門一課的主題，現在只要照著用就好，不用糾結為什麼。

Shadowing：重複用同一個名字

Rust 允許你用 let 重新宣告同名變數，這叫 shadowing，跟 mut 不一樣：

let count = 10;
let count = count + 1; // 產生一個新的 count，蓋掉舊的
println!("count = {}", count); // 11

差別在於：mut 是同一個變數改值；shadowing 是用同一個名字重新綁定一個新的變數（甚至型別可以不一樣）。

實務上：mut 跟 shadowing 怎麼選？

兩個都可以「蓋掉」原本的名字，但解決的是不同的問題 —— 判斷點在於：這個值的本質有沒有變？

用 mut： 概念上是同一件事、只是狀態隨時間演進，型別通常不變。

// 迴圈計數器 / 累加器
let mut total = 0;
for n in [1, 2, 3, 4] {
    total += n; // 同一個 total，值持續累加
}

// 逐步組裝一份字串
let mut log = String::new();
log.push_str("start\n");
log.push_str("processing\n");

用 shadowing： 沿用同一個名字，做一連串轉換，型別甚至可能改變 —— 最典型的例子是處理使用者輸入：

let input = "42";                          // &str，來自使用者輸入
let input = input.trim();                  // 還是 &str，去掉頭尾空白
let input: i32 = input.parse().unwrap();   // 變成 i32，型別都換了

這三個 input 其實是三個不同的變數，只是概念上「這就是使用者輸入這件事，只是形式不斷精煉」，所以刻意共用名字，省去發明 input_str、input_trimmed、input_num 這類命名。

安全性才是關鍵判斷點： shadowing 比 mut 更安全，因為每次 let 都產生新的不可變綁定，轉換完之後那個值預設又是不可變的，不用擔心後面某行不小心把它改掉。經驗法則：型別會變、或是幾個離散步驟的轉換 → shadowing；型別不變、持續性的迴圈式狀態演進 → mut。不確定時優先選 shadowing，它給的保護比較多。
