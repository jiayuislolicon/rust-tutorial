Ownership：值只有一個主人

目標：看懂 value borrowed here after move 這個錯誤，知道它為什麼發生，並修好它。

這一課要處理一個你遲早會撞到的編譯錯誤。它背後是 Rust 最核心的機制，叫 ownership（所有權）。

內容分兩課。這課講「移動」。下一課講「借用」，也就是你一直在寫的那個 &。

一個會讓你意外的錯誤

let s1 = String::from("notes.txt");
let s2 = s1;
println!("{}", s1);

這段程式在大多數語言裡都能跑。Rust 編譯不過： 

error[E0382]: borrow of moved value: `s1`
  |
2 |     let s1 = String::from("notes.txt");
  |         -- move occurs because `s1` has type `String`,
  |            which does not implement the `Copy` trait
3 |     let s2 = s1;
  |              -- value moved here
4 |     println!("{}", s1);
  |                    ^^ value borrowed here after move

注意 move 這個字。let s2 = s1; 做的不是複製，是把字串交給 s2。

字串本身沒有搬動，也沒有被清空。改變的只有一件事：誰擁有它。

而交出去之後，s1 就不能再用了。

先講一個詞：作用域

要理解上面那個規則，需要先知道變數什麼時候會消失。 

fn main() {
    {
        let s = String::from("hi");
        println!("{}", s);      // 這裡可以用 s
    }
    println!("{}", s);          // 錯誤：s 已經不在了
}
error[E0425]: cannot find value `s` in this scope

作用域就是一個變數存在的範圍。通常就是包住它的那對大括號 { }。執行離開那對大括號，變數就消失。

變數消失的時候，它的字串內容也會被清掉，那塊記憶體交還給系統。這個動作叫釋放。

你不需要寫任何程式碼去叫它釋放。Rust 自動做。這就是 Rust 不需要垃圾回收（GC）的原因。

三條規則

  • 每一個值都有一個擁有者（owner）。
  • 同一時間只能有一個擁有者。
  • 擁有者離開作用域時，值就被釋放。

第二條看起來很嚴格。它為什麼必須存在？

假設 Rust 允許 s1 和 s2 同時擁有同一份字串。

執行離開大括號時，兩個變數都會消失。按照第三條規則，兩個都會去釋放那份字串。同一塊記憶體被釋放了兩次。

這在 C 和 C++ 裡是一類很有名的 bug，叫 double free。結果是程式崩潰，或是變成安全漏洞。

Rust 的解法很直接：交出去之後，原本的變數就不能用。所以永遠不會有第二次釋放。

數字為什麼不一樣

let n1 = 5;
let n2 = n1;
println!("n1 = {}, n2 = {}", n1, n2);   // 兩個都能用

這段完全合法。整數不會被移動，會被複製。

原因寫在前面那個錯誤訊息裡：does not implement the Copy trait。

Rust 的規則只有一條：型別上有 Copy 這個標記，賦值時就是複製。沒有，就是移動。

trait 是什麼？可以先想成「這個型別具備某種能力」的標記。之後有專門一課講它。現在只需要記住上面那一條規則。

哪些型別有這個標記？ 

// 有 Copy
i32  i64  u8  usize      // 各種整數
f64  f32                 // 浮點數
bool                     // true / false
char                     // 單一字元

// 沒有 Copy
String
Vec<T>

分界線不是「整數 vs 其他」。是大小固定 vs 可以增長。

i32 永遠佔 4 bytes，編譯時就知道。複製一份幾乎不花時間，所以 Rust 直接幫你做。

String 的長度要到執行時才知道，可能 3 個字，也可能 300 萬個字。複製它要另外要一塊記憶體，再把整份內容搬過去。

Rust 不會偷偷幫你做這種昂貴的事。要複製字串，你得自己寫出來。

函式呼叫也會移動

這才是你實際寫程式時真正會踩到的地方： 

fn show(name: String) {
    println!("處理 {}", name);
}

fn main() {
    let filename = String::from("notes.txt");
    show(filename);
    println!("再用一次 {}", filename);   // ← 編譯錯誤
}

把 filename 傳進 show，所有權就交給參數 name 了。

show 執行完，name 離開作用域，字串被釋放。

回到 main 的時候，字串已經沒了。所以 filename 不能再用。錯誤訊息跟前面那個一模一樣：value borrowed here after move。

兩種修法

第一種是 clone，明確地複製一份給函式： 

show(filename.clone());
println!("再用一次 {}", filename);   // ✅ 可以編譯

這樣能跑，但它真的複製了一整份字串。Rust 要你把這個成本寫出來，而不是替你藏起來。

第二種是借用。編譯器其實已經在提示你了： 

note: consider changing this parameter type in function `show`
      to borrow instead if owning the value isn't necessary

show 只是把字串印出來，它不需要擁有這個字串。這種情況就該用 &。

這是下一課的主題。也是你從 Lesson 4 一直在寫、但還沒解釋過的那個符號。

小測驗一：let s1 = String::from("hi"); let s2 = s1; 之後，s1 怎麼了？
小測驗二：let n2 = n1;（n1 是 i32）之後 n1 還能用。因為整數有哪個標記？（英文，4 個字母）

換你動手

這次要你故意製造錯誤，再修好它。認得出錯誤比背得出規則有用。

在 hello_cli/src/main.rs 加一個函式：

fn summarize(content: String) {
    println!("共 {} 行", content.lines().count());
}

然後在讀檔成功的那條分支裡呼叫它，並且在呼叫之後再印一次 content。

三個步驟：
  • 先寫成 summarize(content)，跑 cargo run -- notes.txt。你應該看到 borrow of moved value。停下來把整個錯誤訊息讀完，確認你能指出哪一行是 value moved here。
  • 用 clone 修好，讓它印出行數和內容。
  • 想一下：summarize 真的需要擁有這個字串嗎？（答案在下一課。）
這一課的成果
你能看懂 borrow of moved value 了。這是 Rust 初學者撞最多次的錯誤（代號 E0382，查資料時用得上）。它不是 bug，是 Rust 保證記憶體安全的機制正在運作。你也知道了為什麼 Rust 程式裡 clone 到處都是：因為 Rust 拒絕偷偷幫你做昂貴的複製。
