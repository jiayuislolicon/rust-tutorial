Lesson 0008 · Rust · CLI 工具養成路線

命令列參數與檔案

目標：能讓程式從命令列接收參數（例如檔名），並讀取該檔案的內容。

前七課的程式都靠 read_line 跟使用者互動 —— 每次執行都要手動打字。真正的 CLI 工具通常是這樣用的：my_tool some_file.txt，參數直接跟在指令後面，程式啟動就知道要處理哪個檔案。這一課補上這塊：讀命令列參數、讀檔案內容。

讀命令列參數

use std::env;

fn main() {
    let args: Vec<String> = env::args().collect();
    println!("{:?}", args);
}
逐行拆解：
  • env::args() 回傳一個「可以走訪的東西（iterator）」，裡面是每一個命令列參數 —— iterator 之後有專門一課，這裡先只需要知道它可以 .collect() 成一個 Vec<String>。
  • args[0] 永遠是程式本身的路徑，不是使用者打的參數。第一個真正的參數是 args[1] —— 例如執行 cargo run -- report.txt，args[1] 就是 "report.txt"。
用 cargo run 傳參數時，習慣上加一個 --： cargo run -- report.txt。準確地說：cargo 會把它認不出來的尾端參數自動轉交給你的程式，所以 cargo run report.txt 其實也能跑。-- 是 Unix 慣例，意思是「選項到此結束，後面全部當成值」—— 它在參數開頭有 - 時才變成關鍵：cargo run --version 會被 cargo 自己吃掉，cargo run -- --version 才會把字串 --version 交給你的程式。建議一律加 --，這樣就不必每次判斷參數會不會被誤認。

讀檔案內容

use std::env;
use std::fs;

fn main() {
    let args: Vec<String> = env::args().collect();
    let filename = &args[1];

    match fs::read_to_string(filename) {
        Ok(contents) => println!("檔案內容：\n{}", contents),
        Err(_) => println!("讀不到檔案 {}，請確認路徑對不對。", filename),
    }
}

fs::read_to_string(filename) 回傳的也是 Result —— 檔案可能不存在、沒權限讀等等，都會是 Err。跟 Lesson 6 一樣，用 match 分開處理，而不是用 .expect(...) 讓程式直接當掉：檔案不存在對 CLI 工具來說是很常見的使用者錯誤，不是程式的 bug，不該讓程式崩潰。

小測驗：執行 cargo run -- notes.txt，args[0] 裡裝的是什麼？（用 3 個字回答，例如「程式路徑」這種長度）
這一課的成果
你現在能寫一個接收檔名當參數、讀取檔案內容、檔案不存在也不會崩潰的 CLI 工具 —— 這是 Lesson 7 那個互動式小工具的「無人值守」版本，也是絕大多數真實 CLI 工具的基本形狀：tool 參數，處理，印結果。

主要參考資料：The Rust Programming Language — 12.1 Accepting Command Line Arguments 與 12.2 Reading a File（官方書籍，繁中版：rust-lang.tw）。想動手練習更多小題，可以搭配 Rustlings 的 clippy 之外，官方 minigrep 專案教程也很值得跟著做一次。
